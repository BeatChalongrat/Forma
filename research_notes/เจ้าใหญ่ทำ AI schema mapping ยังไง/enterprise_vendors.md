# How large enterprise data-integration and cloud vendors use AI/LLMs for schema mapping and transformation of heterogeneous files — and how they make the output trustworthy

Research date: 2026-11-02. Scope: Informatica, Microsoft, Google, AWS, Snowflake, Databricks, SAP, Oracle, Palantir, Alteryx/Trifacta, Tamr, Ataccama, Collibra, plus analyst notes and the Microsoft Research PROSE/FlashFill lineage. Vendor terminology is quoted as the source uses it. Facts marked "(search snippet, not fetched)" came from a search engine summary of a page I could not open (docs.informatica.com and businesswire.com return HTTP 403; several Palantir/Snowflake pages were navigation-only).

---

## Key question 1 — What exactly does each vendor's AI produce, and is it declarative (mapping spec) or code?

### Takeaway
The field splits cleanly. Integration-platform vendors whose product already has a declarative asset model (Informatica mappings, Oracle mapper XSLT, Trifacta "Wrangle" recipes, Data Fusion "directives", BigQuery data-prep steps, Tamr "unified attributes", Dataverse column maps) have the AI emit that same declarative asset, which their existing validators and canvases can then check. Code-first platforms (AWS Glue/Amazon Q, SageMaker Canvas, Databricks Genie Code/Lakeflow Designer, Snowflake Cortex Code, Fabric Copilot, Collibra SQL AI) have the AI emit code (PySpark, Python, SQL, Power Query M) that the user reviews in an editor. Document-extraction services (Content Understanding, Snowflake Document AI/AI_EXTRACT, Databricks ai_extract) emit *values against a user-supplied schema* with per-field confidence and grounding, not mappings.

### Cited Findings

**Informatica (IDMC / Cloud Data Integration)**
- "CLAIRE recommendations" appear during mapping design and cover eight recommendation types: transformation types to include; additional sources based on primary/foreign-key relationships; joining or unioning additional sources; objects in a mapping inventory; mapplets or user-defined functions; ways to standardize data; ways to mask sensitive data; rule specifications. Not available for mappings in "SQL ELT mode". — [Informatica, CLAIRE recommendations](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/CLAIRE_recommendations.html)
- "Automapping" is "a CLAIRE capability that provides recommendations to automatically match and align data integration sources and targets during mapping design"; it "generates a set of mapping suggestions based on matching data fields' names, structures, and data types", and it "learns the underlying structure and patterns in a mapping to identify source table relationships". The output is a mapping on the canvas that the user then saves and validates; supported transformations are Source, Target, Hierarchical target (MDM), Filter, Expression, Normalizer, Joiner. — [Informatica, Automapping](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/Automapping.html)
- "CLAIRE Copilot for Data Integration" generates (a) a mapping "from a use case and data flow described in the conversation window", (b) configured transformations on the canvas, (c) expressions for Aggregator and Expression transformations (from natural language or pseudocode), and (d) "brief summary" / "detailed summary" explanations of existing mappings. It "doesn't create or summarize mappings in advanced mode or in SQL ELT mode." — [Informatica, Using CLAIRE Copilot with Data Integration](https://onlinehelp.informatica.com/IICS/dev/CDI/en/dd-cloud-copilot/Using_CLAIRE_Copilot_with_Data_Integration.html)
- The Copilot "determines the asset type, configures it, and creates it", and "you can use the asset that CLAIRE Copilot creates as is, or you can manually edit it according to your requirements." — [Informatica, Using CLAIRE Copilot](https://onlinehelp.informatica.com/IICS/prod/CDI/en/dd-cloud-copilot/Using_CLAIRE_Copilot.html) (search snippet, not fetched)
- The intermediate representation is declarative and proprietary: Informatica says it has "our own grammar as to how this describes the mapping, what describes the data quality rule, what describes an MDM asset", and that "the natural language translated into Informatica grammar is where our secret sauce comes in" (Pratik Parekh, SVP/GM Cloud Integration). Specialized language models are "fine-tuned for data management, translating natural language into Informatica's internal grammar." — [VentureBeat, 31 Jul 2025](https://venturebeat.com/ai/enterprise-data-fragmentation-isnt-going-away-how-informatica-has-evolved-its-ai-capabilities-to-solve-real-challenges)
- "Intelligent Structure Discovery" (ISD) takes a sample file and produces an "intelligent structure model" of the underlying structure that is attached to a complex-file data object; since 10.4.0 it can "create model from sample at design time" for XML, JSON, ORC, Avro and Parquet, and "unidentified data is output in the model in structured JSON format." — [Informatica 10.4.1 Release Guide](https://onlinehelp.informatica.com/analyst/10.4.1/en/release-guide/Intelligent_Structure_Model.html) (2019-era material, still current in Cloud Data Integration)
- ISD "data drift": when input contains fields missing from the sample, "the undefined data goes to an unassigned port on the target rather than being dropped." — [Informatica, Data drift](https://docs.informatica.com/data-integration/powercenter/10-4-0/new-features-guide/new-features--10-2-2-/big-data-management/intelligent-structure-model/data-drift.html) (search snippet, not fetched)
- Fall 2025 release shipped prebuilt "CLAIRE Agents": Data Quality Agent (creates DQ rules, public preview), Data Exploration Agent, Enterprise Discovery Agent, "ELT Agent" (builds data pipelines), Product Help Agent, Product Experience Agent; all GA except Data Quality Agent. — [TechTarget, 29 Oct 2025](https://www.techtarget.com/searchDataManagement/news/366633382/Informatica-launches-agents-adds-new-AI-development-tools)
- 2026 lineup also includes "CLAIRE Copilot for NL to XQuery" (NL → XQuery code) and "CLAIRE Copilot for Data Quality" that "converts business data quality standards into executable rules and checks for duplicate rules." — [SoftwareReviews/Info-Tech, 18 Mar 2026](https://www.softwarereviews.com/vendor-technology-notes/informatica-introduces-ai-agents-but-does-not-become-an-agentic-ai-platform-yet)

**Microsoft**
- Copilot in Fabric Data Factory "provides intelligent Mashup code generation to transform data using natural language input" for Dataflow Gen2, plus "code explanations"; for pipelines it does "Pipeline Generation", "Error message assistant", "Summarize Pipeline", "Build expressions". Output is Power Query M code appearing as steps in the Applied Steps list. — [Microsoft Learn, Copilot in Data Factory overview (updated 2026-08-31)](https://learn.microsoft.com/en-us/fabric/data-factory/copilot-fabric-data-factory)
- Dataverse "New import from Excel (preview)": "Assisted mapping: Uses vector-based search to provide more contextually relevant column mapping suggestions"; output is a column map (source column → target attribute), plus sheet selection and a required primary key for upsert. — [Microsoft Learn, Import data from Excel (updated 2026-01-16)](https://learn.microsoft.com/power-apps/maker/data-platform/data-platform-import-export)
- Power Query "Add Column from Examples" (2018): "You know the data result you want in the new column, but you're not sure which transformation (or collection of transformations) will provide that result" — the user types example outputs and Power Query infers the transformation and emits an M formula. — [Microsoft release notes, April 2018](https://docs.microsoft.com/en-us/business-applications-release-notes/april18/data-integration/smart-data-preparation-capabilities-add-column-examples) (older material)
- The underlying engine, PROSE: "Given a domain-specific language (DSL) and input-output examples for the desired program's behavior, PROSE synthesizes a ranked set of DSL programs that are consistent with the examples." Shipped components include Transformation.Text (string transforms from examples), Split.Text, Matching.Text, Read.FlatFile (CSV/fixed-width parsing), extraction for JSON/PDF/web/spreadsheets; product integrations listed include Excel Flash Fill, Power Query/Power BI (Web by Example, PDF tables), Azure Data Factory, PowerShell ConvertFrom-String, Azure Monitor custom fields. — [Microsoft Research PROSE](https://www.microsoft.com/en-us/research/group/prose/)
- FlashFill origin (POPL 2011): the algorithm "can rank multiple solutions and has fast convergence, it can detect noise in the user input, and it asks the user for outputs on inputs that have several plausible interpretations." — [Gulwani, Automating String Processing in Spreadsheets using Input-Output Examples](https://www.microsoft.com/en-us/research/publication/automating-string-processing-spreadsheets-using-input-output-examples/) (2011, older material)
- Azure Content Understanding produces field values against a user-defined field schema with field methods `extract`, `classify`, `generate`; per-field confidence (0–1) and grounding (page, bounding box, character span) are available for all three methods in the `2025-11-01` GA API. — [Microsoft Learn, Analyzer improvement](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement)

**Google Cloud**
- BigQuery data preparation: "Data preparations are BigQuery resources, which use Gemini in BigQuery to analyze your data and provide intelligent suggestions for cleaning, transforming, and enriching it." Each suggestion is a card with "the high-level category of the step, such as Keep rows or Transformation", a plain-language description and "the SQL expression that runs the step". Step types: Source, Transformation, Filter, Deduplicate, Validation, Join, Destination, Delete columns. Pipelines are scheduled through Dataform. — [Google, Introduction to BigQuery data preparation](https://docs.cloud.google.com/bigquery/docs/data-prep-introduction)
- Gemini tasks listed: "Applying transformations and data quality rules, Standardizing and enriching data, Automating schema mapping." For prompt-based steps "Gemini generates a SQL expression and a new description based on your prompt." For uploaded files "Gemini checks your file for column names. If it doesn't find any, it provides suggestions." — [Google, Prepare data with Gemini](https://docs.cloud.google.com/bigquery/docs/data-prep-get-suggestions)
- Cloud Data Fusion "Wrangler": a recipe is a set of "directives" (one directive per step, applied in order); the preview updates as directives are added. No Gemini/LLM feature is documented for Wrangler. — [Google, Wrangler overview](https://docs.cloud.google.com/data-fusion/docs/concepts/wrangler-overview)
- Dataplex/BigQuery "data insights": Gemini "provides table description, column descriptions, and profile scan output based on the table's metadata" and "uses profile scan output (if available) to ground the generated descriptions"; max 350 columns per table. — [Google, Generate data insights](https://docs.cloud.google.com/bigquery/docs/data-insights)

**AWS**
- "Amazon Q data integration in AWS Glue" lets users "build integration jobs by describing what they want in plain language"; it generates PySpark code. The docs warn: "generative AI technology is new and there can be mistakes, sometimes called hallucinations, in the responses. Test and review all code for errors and vulnerabilities before using it." — [AWS Glue docs, Amazon Q data integration](https://docs.aws.amazon.com/glue/latest/dg/q.html)
- 2025 expansion: Q now generates "DataFrame-based code" that works "across any Spark environment" (earlier: AWS Glue DynamicFrame only); supports S3 (CSV/JSON/Parquet), Hudi/Delta/Iceberg, 20+ sources; transforms limited to "filters, projections, unions, joins, and aggregations"; "in-prompt context awareness" pulls connection properties and transform settings from the prompt; missing details become placeholders such as `<s3-path>`. — [AWS Big Data Blog](https://aws.amazon.com/blogs/big-data/amazon-q-data-integration-adds-dataframe-support-and-in-prompt-context-aware-job-creation)
- SageMaker Canvas "Chat for data prep": "The responses to your prompts generate code for your transformations and analyses. You can modify the code to update the output from the prompt." Requires Amazon Bedrock access to "the Anthropic Claude model". — [AWS, Chat for data prep](https://docs.aws.amazon.com/sagemaker/latest/dg/canvas-chat-for-data-prep.html)
- Glue DataBrew: profiling output "helps you understand your dataset and decide what kind of data preparation steps you might want to run in your recipe jobs"; DataBrew recipes are declarative step lists (250+ built-in transformations). No LLM feature found. — [AWS DataBrew, Profile jobs](https://docs.aws.amazon.com/de_de/databrew/latest/dg/jobs.profile.html)

**Snowflake**
- `AI_EXTRACT` "specializes in extracting structured data based on a schema" (text, tables, checkboxes, handwriting); a "model registry stores document extraction models fine-tuned for custom use cases"; `AI_CLASSIFY` routes document types to downstream extraction. — [Snowflake, Working with Document AI](https://docs.snowflake.com/user-guide/snowflake-cortex/document-ai/working-with-document-ai)
- Document AI model build: "Define the data values to be extracted by asking questions using natural language", "Review the results provided by the model", then "Decide to either publish the model or fine-tune the model to improve the results"; publishing "enables using the latest version of the model build in production", and a version number is passed to `PREDICT`. — [Snowflake tutorial](https://docs.snowflake.com/user-guide/snowflake-cortex/document-ai/tutorials/create-processing-pipelines); [Snowflake quickstart](https://quickstarts.snowflake.com/guide/doc-ai-pipeline-automation)
- "Cortex Code" (GA in Snowsight 26 Mar 2026) can "generate, modify, optimize, and explain SQL and Python through conversation"; "Agent Teams" lets a lead agent coordinate role-based teammates; "skills" are packaged instructions for data tasks. — [Snowflake blog](https://www.snowflake.com/en/blog/cortex-code-snowsight/)
- Openflow is "an integration service that connects any data source and any destination", built on Apache NiFi; the About page documents no AI/LLM-assisted mapping. — [Snowflake, About Openflow](https://docs.snowflake.com/en/user-guide/data-integration/openflow/about). Connector-level "Schema Evolution Enabled" lets Snowflake "automatically expand the destination table by adding new columns that are detected in the incoming stream and dropping NOT NULL constraints" (rule-based, not AI). — [Openflow Kafka connector](https://docs.snowflake.com/user-guide/data-integration/openflow/connectors/kafka/setup)

**Databricks**
- Lakeflow Designer (Public Preview 23 Apr 2026, GA June 2026): "Each visual transformation produces Python code" that "can be reviewed, versioned in Git, and integrated into larger production workflows"; built on "Genie Code", "Databricks' native agentic coding assistant." — [Databricks blog](https://www.databricks.com/blog/announcing-public-preview-lakeflow-designer)
- In Designer, Genie Code "adds, configures, and connects operators", writes "column expressions, filter conditions, and join conditions", diagnoses failed operators; when Genie Code is unavailable "Lakeflow Designer hides its AI features, and you configure operators by hand." — [Databricks docs, Genie Code in Designer](https://docs.databricks.com/aws/en/designer/genie-code)
- For documents, Genie Code builds a Lakeflow job whose stages are SQL AI functions: `ai_parse_document`, `ai_classify`, `ai_extract` ("pulls structured fields against a schema, with citations and confidence scores"), then publishes to a Unity Catalog table; the user "review[s] the generated SQL and tasks" before running. — [Databricks docs, Genie Code for IDP](https://docs.databricks.com/aws/en/large-language-models/genie-code-document-processing)

**SAP**
- "Joule with SAP Datasphere" lets users "ask Joule how to use Datasphere features and get answers that link to product documentation" and "carry out tasks from the conversation without the user opening the Datasphere interface"; requires Joule Base; "AI Units are currently required". — [SAP product page](https://www.sap.com/products/technology-platform/joule-with-sap-datasphere.html)
- Datasphere is Business Data Cloud's semantic layer "used for mapping business logic as virtual models or persisting data in the object store." — [SAPinsider](https://sapinsider.org/articles/what-actually-is-saps-business-data-cloud/)
- Joule in SAP Business Application Studio has `/hana-sql-gen` (creates SAP HANA Cloud SQL) and `/hdi-gen` (generates artifact definitions from natural language) — HANA tooling, not Datasphere. — [SAP Learning](https://learning.sap.com/courses/developing-data-models-with-sap-hana-cloud/working-with-joule-in-sap-business-application-studio)

**Oracle**
- Oracle Integration 3 mapper "Recommend" option "generates mapping recommendations based on metadata and mapping combinations that are stored in a public mapper repository" that "contains metadata and mapping combinations from recipes and accelerators"; output is "Direct mapping", "Functions/operators" (many-to-one), or "XSLT constructs like for-each statements" — i.e., declarative XSLT. Max three sources; "This AI feature is available only within a project"; adapters limited to Oracle ERP Cloud, FTP, NetSuite, Salesforce, HCM Cloud, CX Sales. — [Oracle docs, Generate Mapping Recommendations](https://docs.oracle.com/en/cloud/paas/application-integration/mapper-user/generate-mapping-recommendations.html)
- Gen-2 "recommendations engine": "By default, the recommendations engine is enabled. When enabled, all integrations on this instance are published to the recommendations engine." — [Oracle docs](https://docs.oracle.com/en/cloud/paas/integration-cloud/mapper-user/accepting-mapping-recommendations-recommendations-engine.html)
- OCI Data Integration data-loader mapping is rule-based: "Map by name" (default), "Map by pattern" (e.g. `*_NAME` → `$1_NAME`, case-sensitive, Java regex option) with "Preview mapping". No AI. — [Oracle OCI docs](https://docs.oracle.com/en-us/iaas/data-integration/using/data-loader-map-attributes.htm)

**Palantir Foundry**
- Pipeline Builder "Generate": select input nodes, enter a prompt, "select Generate"; "The output is one or more transform nodes highlighted in purple, with a description of the generated transforms"; "Generated transforms are saved to pipeline logic like any other transform" (i.e., the output is Pipeline Builder's own declarative transform nodes, not free code). "Transform Assist" includes a "Regex helper" and "Timestamp formatter" (paste example timestamps → generated formats). — [Palantir, AIP features in Pipeline Builder](https://palantir.com/docs/foundry/pipeline-builder/pipeline-builder-aip/)
- "Use LLM" node runs an LLM per row with templates (Classification, Summarization, Translation, Sentiment, Entity extraction) or custom prompt; "Struct output uses strict parsing. If the LLM response doesn't match the schema, the node fails with 'Cannot coerce to provided output type.'" — [Palantir, Use LLM node](https://palantir.com/docs/foundry/pipeline-builder/pipeline-builder-llm/)
- AIP Logic: "a no-code development environment for building, testing, and releasing functions powered by LLMs"; inputs are Ontology objects or text; outputs are objects/strings or Ontology edits. — [Palantir, AIP Logic overview](https://www.palantir.com/docs/foundry/logic/overview/)

**Alteryx / Trifacta**

Output is a Wrangle recipe step. — [Alteryx help, Overview of Predictive Transformation](https://help.alteryx.com/aac/en/trifacta-classic/concepts/feature-overviews/overview-of-predictive-transformation.html) (search snippet; page body did not load)

- Current assistant "Ask Alteryx" "uses Generative AI to analyze your current workflow and provide tailored recommendations"; 4 Jun 2026 entry: continue workflow development in Designer from Alteryx One. — [Alteryx release notes](https://help.alteryx.com/release-notes/en/ask-alteryx-release-notes.html)

**Tamr**
- Schema mapping is "a categorization task, where unified attributes are the categories and the model finds the best fit for each input attribute"; output is attribute → unified-attribute mapping suggestions with a similarity score. — [Tamr docs, Mapping Recommendations](https://docs.tamr.com/new/docs/using-machine-learning-with-schemas)
- Newer platform: "LLM-based AI agents surface edge cases for curator review and suggest edits to golden records"; "Confidence thresholds guide automated merges, while uncertain cases are flagged for human review." — [Tamr, Entity resolution](https://tamr.com/entity-resolution)

**Ataccama**
- "Rule suggestions" are of two kinds: "profiling-based" (from "Patterns and irregularities identified in the profiling statistics" and term associations) and "AI-based", which "adds suggestions on top of profiling-based ones", at attribute level, and "available only in Ataccama Cloud deployments". Suggested rules are drawn from the existing rule library (Data Quality > Rules). — [Ataccama docs, Rule suggestions](https://docs.ataccama.com/one/latest/data-quality/rule-suggestions.html)
- ONE AI "converts plain text into actionable rules" (Ataccama's rule language). — [Ataccama AI page](https://www.ataccama.com/ai); Bloor: translates plain-English rule text into Ataccama's scripting language — [Bloor](https://bloorresearch.com/solutions/ataccama-and-data-quality/)

**Collibra**
- "AI-driven rule suggestions" (Unified Data Quality, 2026.08): "analyzes your column metadata and profiling statistics"; each suggested rule shows "Primary column, Data type, Description, SQL query, and AI rationale", grouped by DQ dimension; output is SQL rules added to the job's Monitors tab. — [Collibra docs](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/ta_suggest-rules.htm)
- "SQL AI": "Suggests custom SQL queries based on your plain-text input" and "Helps troubleshoot malformed or syntactically incorrect SQL queries"; prompt "is sent to the Collibra AI proxy"; cloud-only, consumes Collibra Units. — [Collibra docs, About SQL AI](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/co_about-ai-sql.htm)

### Inferences
- The declarative-vs-code split tracks the product's pre-existing asset model, not the vendor's AI philosophy. Every vendor that already owned a validator for a declarative artifact (Informatica mapping grammar, Oracle XSLT, Palantir transform nodes, BigQuery step SQL expressions, Trifacta Wrangle, Tamr unified attributes) kept the LLM inside that artifact. FORMA's `MappingDocument` DSL is the same pattern as Informatica's "own grammar".
- Informatica is the only vendor claiming to *fine-tune* models onto its intermediate grammar; everyone else appears to prompt a general model and parse the result.
- "Schema mapping" as a distinct AI feature for *files* is rare. Only Informatica Automapping, Dataverse assisted mapping, Oracle mapper Recommend, Tamr, and BigQuery "Automating schema mapping" address field-to-field mapping; the rest generate transformation steps and leave mapping to the user or to name-matching rules (OCI "Map by name", Openflow "first-level keys").

### Gaps
- Informatica's official pages on CLAIRE GPT / Copilot internals (docs.informatica.com) return 403; the "Informatica grammar" details come only from VentureBeat's interview.
- No documentation found describing what BigQuery data prep's "Automating schema mapping" concretely does beyond creating the destination table from the current schema.
- SAP: no official source found describing Joule-driven source-to-target mapping in Datasphere or Business Data Cloud; only documentation-Q&A and task execution are documented.
- Snowflake Openflow: no AI-assisted mapping feature found; Cortex Code generating "Openflow CDC" pipelines is asserted only by Capgemini, not Snowflake.
- Cloud Data Fusion: no Gemini feature found in docs; appears to have no LLM assist.
- Alteryx: the predictive-transformation page body would not load in any locale; the Trifacta Dataprep mirror redirected to a product overview.

## Key question 2 — Which vendors execute the AI's proposal on sample data and loop results back (to the model or to the user) before commit?

### Takeaway
Preview-on-sample before commit is universal in the data-prep tools (BigQuery data prep ~10k-row sample, Fabric Dataflow Gen2 preview, SageMaker Canvas "Preview" then "Add to steps", Trifacta suggestion preview, Wrangler preview, Palantir "Trial run", Oracle "Preview mapping"). Only two vendors document a loop where results go *back to the model* automatically: Databricks Genie Code (runs a transformation, inspects output, retries; runs field-level evaluation and proposes prompt-description fixes as a diff) and Palantir AIP Evals (categorizes failing test cases by root cause and suggests prompt edits). Everyone else closes the loop through a human.

### Cited Findings
- **Google BigQuery data prep**: when a table is opened "a BigQuery job using your credentials creates sample rows in a temporary table in the same project"; samples are "about 10k rows: TABLESAMPLE for standard tables, or a selection from the first 1 million rows for views and external tables", expire in ~24 h and are not refreshed automatically; each card can be previewed, edited or applied; the data view shows "a histogram of each column's top values." — [Google, data prep intro](https://docs.cloud.google.com/bigquery/docs/data-prep-introduction); "Select a card, then use Preview to see the result, Edit to change it in natural language, or Apply to add it as a step." — [Google, Prepare data with Gemini](https://docs.cloud.google.com/bigquery/docs/data-prep-get-suggestions)
- **Microsoft Fabric Dataflow Gen2**: the training module frames the work as "a cycle of prompt → output → validation → refinement"; "Copilot might produce inaccurate results when the intent is to evaluate data that isn't present within the sampled results imported into the session's data"; "Validate important rules against the full dataset after running the dataflow." The "Undo action can remove the last Copilot change before another edit." — [Microsoft Learn module (updated 2026-10-26)](https://learn.microsoft.com/en-us/training/modules/get-started-copilot-fabric-data-engineering/dataflow-gen2); limitation list — [Copilot in Data Factory overview](https://learn.microsoft.com/en-us/fabric/data-factory/copilot-fabric-data-factory)
- **AWS SageMaker Canvas**: "you can view a preview that shows how data is being transformed. You can choose to add it as step in your Data Wrangler flow based on what you see in the preview"; flow is Preview → (optionally modify code and Update) → "Add to steps". — [AWS docs](https://docs.aws.amazon.com/sagemaker/latest/dg/canvas-chat-for-data-prep.html)
- **AWS Glue / Amazon Q**: no automated execution; in the visual editor users "inspect the join configuration, open the generated script ('Show script'), and preview the data that will be written"; in Glue Studio users copy code into the script editor, attach an IAM role and run; in notebooks a suggestion is accepted with Tab. — [AWS Big Data Blog](https://aws.amazon.com/blogs/big-data/amazon-q-data-integration-adds-dataframe-support-and-in-prompt-context-aware-job-creation)
- **Databricks Genie Code (Designer)**: Genie Code "can also run a transformation, inspect the output, and try another approach if a join fails or returns no rows"; "Each step is a visual operator with a data preview. Users can see what changed, where rows were filtered, how a join was resolved, and what the output looks like before moving to the next step." — [Databricks blog, Apr 2026](https://www.databricks.com/blog/announcing-public-preview-lakeflow-designer)
- **Databricks Genie Code (documents)**: "Start on a sample, review the output, evaluate quality, and iterate before processing the full dataset." Evaluation loop: "Genie Code runs field-level evaluation against a labeled table of expected outputs. It proposes fixes, usually sharper field descriptions, as a diff you approve. Each accepted change is re-evaluated with before-and-after results, and the loop repeats until quality meets your bar." The "Document Parsing UI shows rendered pages beside parsed content and extracted fields" to separate parsing errors from extraction errors. — [Databricks docs](https://docs.databricks.com/aws/en/large-language-models/genie-code-document-processing)
- **Palantir Use LLM**: "Trial run" tab — enter a value and Run, or in the "Input table" tab select rows and choose "Use rows for trial run"; the `</>` icon shows "the initial prompt, intermediate outputs (including failed ones), corrections, and the final output." — [Palantir, Use LLM node](https://palantir.com/docs/foundry/pipeline-builder/pipeline-builder-llm/)
- **Palantir Evaluation suite**: "configure multiple evaluations in an evaluation suite and run them in an isolated test environment to observe their behavior"; evaluators include Exact string match, Integer range, Exact numeric match, array matches, temporal match/range, Levenshtein distance, String length, Keyword checker, Regex match, and "LLM-as-a-judge"; results stored in an output dataset with pass/fail per row. — [Palantir, Evaluation suite](https://palantir.com/docs/foundry/pipeline-builder/evaluation-suite/)
- **Palantir AIP Evals** (for AIP Logic) "categorizes failing test cases by root cause" and suggests targeted prompt edits. — [Palantir, AIP Logic overview](https://www.palantir.com/docs/foundry/logic/overview/)
- **Palantir Generate** (pipeline assistant): docs describe no preview or validation step; generated nodes are highlighted purple and saved like any transform; the user re-prompts via "Back to generate". — [Palantir, AIP features](https://palantir.com/docs/foundry/pipeline-builder/pipeline-builder-aip/)
- **Snowflake Document AI**: human review of model answers in the build UI ("confirming or correcting the answers that the model provided"), then publish or fine-tune. — [Snowflake tutorial](https://docs.snowflake.com/user-guide/snowflake-cortex/document-ai/tutorials/create-processing-pipelines)
- **Oracle OCI Data Integration**: "Select Preview mapping to verify that the identified source attributes and target attributes are the attributes that you want to map", then adjust patterns and preview again. — [Oracle OCI docs](https://docs.oracle.com/en-us/iaas/data-integration/using/data-loader-map-attributes.htm)
- **Oracle Integration 3 mapper**: recommendations appear in a Sources / "Recommended mapping" / Target view; per-mapping "Include" checkbox; "Apply Recommendations" to accept; "Show mappings" toggles existing vs recommended. — [Oracle docs](https://docs.oracle.com/en/cloud/paas/application-integration/mapper-user/generate-mapping-recommendations.html)
- **Trifacta/Alteryx**: "Suggestions are previewed before you commit, and you can edit them." — [Alteryx help](https://help.alteryx.com/aac/en/trifacta-classic/concepts/feature-overviews/overview-of-predictive-transformation.html) (search snippet)
- **Google Wrangler**: "The data preview updates as you add directives, so you can see each change's effect before running the pipeline." — [Google, Wrangler overview](https://docs.cloud.google.com/data-fusion/docs/concepts/wrangler-overview)
- **Collibra AI rule suggestions**: Preview pane shows SQL + "AI rationale"; "Apply rules" to create; "The AI never accesses your actual data rows." — [Collibra docs](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/ta_suggest-rules.htm)
- **Ataccama**: Configuration tab shows "a profiling preview, description, and suggestion reasoning"; Implementation tab shows rule logic; hover shows why suggested. — [Ataccama docs](https://docs.ataccama.com/one/latest/data-quality/rule-suggestions.html)
- **Microsoft Content Understanding**: "Auto label runs the existing analyzer and prepopulates results that you can edit" — labeled corrections are fed back and the analyzer is rebuilt; "Evaluate extraction quality before and after training to confirm that the samples improve results." — [Microsoft Learn](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement)
- **Dataverse import preview**: "Review the summary and select Import"; third-party walkthrough reports mappings grouped as Mapped / Possible Match / Unmapped and that the import button stays disabled until possible matches are reviewed. — [Microsoft Learn](https://learn.microsoft.com/power-apps/maker/data-platform/data-platform-import-export); [Inogic, Aug 2025](https://www.inogic.com/blog/2025/08/simplify-excel-data-imports-with-ai-assisted-mapping-in-dataverse/)
- **Informatica Copilot**: no documented preview/validation specific to generated assets; the standard mapping canvas "save and validate" applies and the asset can be edited. — [Informatica, Automapping](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/Automapping.html); [Informatica, Using CLAIRE Copilot](https://onlinehelp.informatica.com/IICS/prod/CDI/en/dd-cloud-copilot/Using_CLAIRE_Copilot.html) (search snippet)

### Inferences
- The industry default is "LLM proposes → deterministic engine executes on a sample → human looks → commit". The model-in-the-loop variants (Databricks, Palantir evals) exist only where the vendor also owns an execution runtime and a labeled expected-output table; they are still gated by a human approving a diff.
- Sampling is the universal weak point: Microsoft explicitly warns that Copilot is wrong when the rule depends on rows outside the preview; Google caps the sample at ~10k rows. For FORMA's "every 14 days, new file" cadence, this argues for validating a proposed mapping against the *whole* file (which FORMA's simulate/sandbox already does) rather than a sample.

### Gaps
- No vendor documents *how long* a sample-to-commit loop takes or how often users reject suggestions.
- Palantir Generate's lack of a preview step may be a documentation omission; the page states nothing either way.

## Key question 3 — How is confidence computed/displayed and used for auto-accept vs review?

### Takeaway
Explicit numeric confidence exists almost only in document-extraction products (Content Understanding, Snowflake AI_EXTRACT/Document AI, Databricks ai_extract) and in Tamr's similarity scores; the mapping/transformation copilots (Informatica, Fabric, Glue, BigQuery, Palantir Generate, Oracle) expose no score at all and rely on the user accepting each suggestion. Microsoft is the only vendor that publicly explains *how* its confidence is computed (a separate confidence model, not LLM self-report) and gives a calibration procedure with numbers.

### Cited Findings
- **Microsoft Content Understanding** — scoring: "Each supported extracted field gets a score from 0 to 1. The score is not the LLM's self-reported certainty. A separate confidence model produces it." Inputs: "where and how the value appears, grounding evidence, field type and schema position, predicted value shape, comparison with labeled examples (where available), and extraction diagnostics such as ambiguity." The same value "can score differently depending on context, such as a top-level field versus a table cell." Microsoft "trains the shared service-level model on Microsoft-curated data, not customer data"; latest refresh "improved AUROC by up to 14%". The post treats scores "as a risk-ranking signal rather than a calibrated probability." — [Microsoft Foundry blog, 14 Oct 2026](https://devblogs.microsoft.com/foundry/content-understanding-confidence-grounding-hitl/)
- **Microsoft** — threshold procedure: collect human-checked documents, measure accuracy and error separation per field, set a business target (e.g. "catching at least 80% of known errors"), choose the cutoff meeting it with the fewest reviews, validate on held-out documents; "If no cutoff meets the target, the field stays in review"; empty fields need a separate policy "because confidence didn't reliably distinguish 'missed' from 'truly empty'"; set thresholds "per document type (form, version, source) and per field"; 0.8 is cited as an example of an *unjustified* rule of thumb. — [same](https://devblogs.microsoft.com/foundry/content-understanding-confidence-grounding-hitl/)
- **Microsoft** — docs example: billing address 0.96 posted directly, amount due 0.52 routed to a human; enabled via `estimateFieldSourceAndConfidence`; purpose "Enables STP (Straight Through Processing)". — [Microsoft Learn, Analyzer improvement](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement); Aug 2026 guidance: "set acceptance thresholds field by field and recalibrate them whenever you switch models." — [Microsoft Foundry blog, Aug 2026](https://devblogs.microsoft.com/foundry/azure-content-understanding-gpt-5-series-guide-model-selection-grounding-improvements-and-confidence-enhancements/)
- **Snowflake AI_EXTRACT** (GA 22 May 2026): pass `scores => TRUE`; response includes a `scoring` object; "Each score is between 0 and 1 and reflects the model's certainty about an extracted value"; entity extraction returns per-field scores, list/table extraction returns aggregate scores; works with default and fine-tuned `arctic-extract`; no extra cost; use to "Set confidence thresholds", "Flag low-scoring extractions for human review", "Build fallback mechanisms". No calibration guidance. — [Snowflake release note](https://docs.snowflake.com/en/release-notes/2026/other/2026-05-22-ai-extract-scores-ga)
- **Snowflake Arctic-Extract fine-tuning**: fine-tuning "widens the gap between confidence scores for correct and incorrect responses, from 0.130 to 0.249", which Snowflake says makes it "easier to define effective confidence thresholds for routing". — [Snowflake engineering blog, May 2026](https://snowflake.com/en/blog/engineering/arctic-extract-fine-tuning/)
- **Snowflake Document AI (Arctic-TILT lineage)**: the 0.8B-parameter TILT-based model was promoted on "reliable confidence scores"; output carries `__documentMetadata.ocrScore` (e.g. 0.968) and a score per field. — [Synced, Aug 2024](https://syncedreview.com/2024/08/22/snowflakes-arctic-tilt-matching-the-power-of-models-1000x-larger-in-document-understanding/amp); [btelligent](https://www.btelligent.com/en/blog/snowflake-document-ai); [InterWorks, Jan 2025](https://interworks.com/blog/2025/01/21/snowflake-cortex-parsing-unstructured-data-with-document-ai)
- **Databricks ai_extract**: fields come "with citations and confidence scores"; "per-field thresholds can be set from evaluation results, and low-confidence rows can be routed to review"; quality = "deterministic checks (schemas, required fields, totals)" + "model confidence" + "business rules" (e.g. "flagging a document where tax paid is greater than salary"); failing docs "quarantined in a separate table for human review". — [Databricks docs](https://docs.databricks.com/aws/en/large-language-models/genie-code-document-processing)
- **Tamr**: "The model tokenizes all values for each attribute and uses MinHash sampling to measure overlap between them"; "assigns each suggestion a score that indicates relative similarity"; users adjust the required similarity to "control how many you review and their quality". — [Tamr docs](https://docs.tamr.com/new/docs/using-machine-learning-with-schemas). Entity resolution: "Confidence thresholds guide automated merges, while uncertain cases are flagged for human review." — [Tamr](https://tamr.com/entity-resolution)
- **Trifacta/Alteryx**: no numeric score; ranking inside a card — "Pattern-based variants usually come first and literal-value variants usually come last", the first variant being "the most specific one applicable to the current selection". — [Alteryx help](https://help.alteryx.com/aac/en/trifacta-classic/concepts/feature-overviews/overview-of-predictive-transformation.html) (search snippet)
- **Dataverse**: three buckets — "Mapped", "Possible Match", "Unmapped" — with review required for possible matches (third-party). — [Inogic](https://www.inogic.com/blog/2025/08/simplify-excel-data-imports-with-ai-assisted-mapping-in-dataverse/)
- **Oracle OIC3**: "The page describes no scores, rankings, or confidence labels. The only match criterion given is that the repository entries are 'similar or close'." — [Oracle docs](https://docs.oracle.com/en/cloud/paas/application-integration/mapper-user/generate-mapping-recommendations.html)
- **Informatica**: neither the CLAIRE recommendations page nor Automapping page mentions confidence; VentureBeat quotes only "high accuracy rates" without numbers. — [Informatica](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/CLAIRE_recommendations.html); [VentureBeat](https://venturebeat.com/ai/enterprise-data-fragmentation-isnt-going-away-how-informatica-has-evolved-its-ai-capabilities-to-solve-real-challenges)
- **Google BigQuery data prep**: no confidence on suggestion cards; trust mechanism is the Validation step — "Failed validation rows go to error table" or fail the run, with a max-error count for file loads. — [Google](https://docs.cloud.google.com/bigquery/docs/data-prep-get-suggestions)
- **Collibra / Ataccama**: no confidence scores; explanation instead ("AI rationale"; "suggestion reasoning"). — [Collibra](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/ta_suggest-rules.htm); [Ataccama](https://docs.ataccama.com/one/latest/data-quality/rule-suggestions.html)
- **Palantir**: Use LLM node has no confidence; failure mode is strict schema coercion error or `Include errors` struct. — [Palantir](https://palantir.com/docs/foundry/pipeline-builder/pipeline-builder-llm/)
- **FlashFill/PROSE ranking** (the historical "confidence" for by-example synthesis): hand-crafted Occam's-razor ranking needed 4.17 examples per task on average; a learned ranker (CAV 2015) that "ranks any correct program higher than all incorrect programs" cut this to 1.48; the 2011 system "asks the user for outputs on inputs that have several plausible interpretations." — [Singh & Gulwani, Predicting a Correct Program in PBE](https://www.microsoft.com/en-us/research/publication/predicting-a-correct-program-in-programming-by-example/) (2015, older material); [Gulwani 2011](https://www.microsoft.com/en-us/research/publication/automating-string-processing-spreadsheets-using-input-output-examples/)

### Inferences
- Where a vendor shows a number, it is a *per-value* extraction score, never a *per-mapping* score. No vendor publishes a confidence for "this source column means this target field." FORMA's per-field policy thresholds therefore have no direct commercial analogue; the nearest are Tamr's adjustable similarity cutoff and Microsoft's per-field STP thresholds.
- Microsoft's design — a separate, non-LLM confidence model fed with grounding evidence, value shape, schema position and labeled-example agreement — is the most concrete public recipe; it validates FORMA's approach of computing confidence from deterministic evidence (header match, value-shape checks, history) rather than asking the model.
- Microsoft's "empty vs missed" finding and "don't use 0.8 as a rule of thumb" are directly transferable lessons for `policies/approval.yaml`.

### Gaps
- No vendor publishes the formula or features of a confidence score for mapping suggestions.
- Snowflake's `scoring` object structure and any calibration guidance live in the AI_EXTRACT function reference, which I did not fetch.
- Alteryx/Trifacta ranking criteria beyond "pattern first, literal last" are undocumented.

## Key question 4 — How do they learn from user corrections across tenants and over time?

### Takeaway
Three distinct learning designs are documented: (1) cross-tenant anonymized metadata pools (Informatica CLAIRE: "anonymous metadata" from other IDMC organizations, opt-in; Oracle Gen-2: all integrations on the instance published to the recommendations engine; Oracle OIC3: a "public mapper repository" of recipes/accelerators); (2) per-project supervised feedback (Tamr accept/reject → "Learn from mappings" job; Content Understanding labeled samples → rebuild analyzer; Snowflake Document AI fine-tune; Trifacta "learns from your selections" and workspace-level "collaborative suggestions"); (3) metadata-grounding loops where accepted outputs become future inputs (Google data insights: saved description "is used to generate future insights"; Databricks Genie Code uses Unity Catalog descriptions, lineage, popularity and example queries). Microsoft states its confidence model is *not* trained on customer data.

### Cited Findings
- **Informatica CLAIRE recommendations**: CLAIRE "uses machine learning" and draws on "anonymous metadata" from prior mappings "across IDMC organizations"; "Recommendations draw on your organization's anonymous mapping metadata only if your organization opts in." Recommendations are on by default for new mappings and off for edits of existing mappings. — [Informatica](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/CLAIRE_recommendations.html)
- **Informatica Automapping**: "learns from the matched records and considers appropriate mapping rules or transformations." — [Informatica](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/Automapping.html)
- **Informatica scale claims**: auto-mapping uses "machine learning trained on millions of integration patterns"; the "metadata system of intelligence" contains "40 petabytes of enterprise data patterns"; early CLAIRE (2018) "drew on metadata from thousands of customer implementations to provide design-time recommendations, runtime optimizations, and operational insights." — [VentureBeat, 31 Jul 2025](https://venturebeat.com/ai/enterprise-data-fragmentation-isnt-going-away-how-informatica-has-evolved-its-ai-capabilities-to-solve-real-challenges). (A third-party listing cites 14 PB instead — conflicting; treat 40 PB as Informatica's own 2025 figure.)
- **Informatica ISD**: models are enriched with new samples via "Update Sample"; new nodes are flagged and a `[NEW]` search pattern locates them; fields absent from the new sample are not removed. — [Informatica, Enriching an existing model](https://docs.informatica.com/integration-cloud/data-integration/current-version/components/refining-intelligent-structure-models/enriching-an-existing-model-with-new-samples.html) (search snippet, not fetched)
- **Oracle Gen-2**: "When enabled, all integrations on this instance are published to the recommendations engine." — [Oracle](https://docs.oracle.com/en/cloud/paas/integration-cloud/mapper-user/accepting-mapping-recommendations-recommendations-engine.html). **OIC3**: recommendations come from "a public mapper repository" of "metadata and mapping combinations from recipes and accelerators" — Oracle-curated, not customer mappings. — [Oracle](https://docs.oracle.com/en/cloud/paas/application-integration/mapper-user/generate-mapping-recommendations.html)
- **Tamr**: iterative loop — create unified attributes and map some input attributes manually or by bootstrapping → "Update the unified dataset" → "Learn from mappings" → "Generate mapping suggestions" → review, accept or reject → repeat; "that feedback gives the model more information"; when new datasets arrive, repeat steps 2–4. — [Tamr docs](https://docs.tamr.com/new/docs/using-machine-learning-with-schemas); [Tamr workflow](https://docs.tamr.com/new/docs/schema-mapping-workflow). Tamr patents cover "suggesting lower-cost mapping paths when a source schema changes, by identifying reusable sequences of modifications." — [Tamr patents](https://www.tamr.com/patents)
- **Microsoft Content Understanding**: "By correcting field values in representative documents, you show the analyzer the relevant layouts, terminology, value patterns, and conventions"; "For datasets with minimal template variations, add a single labeled sample. For more complex variations, add a representative sample for each template or format"; after adding samples "rebuild the analyzer". The `2026-06-01-preview` training "distills the relevant patterns and domain context from the labeled samples into the built analyzer" and "Doesn't include or retain the labeled sample documents in the built analyzer." Limitation: "Labeled samples don't correct text recognition problems." — [Microsoft Learn](https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/document/analyzer-improvement)
- **Microsoft confidence model**: trained "on Microsoft-curated data, not customer data"; customers calibrate thresholds locally; an "outer loop" samples human-checked results (including unflagged ones) to detect drift; recalibrate when "document versions, sources, analyzer configuration, field schema, or the underlying LLM change." — [Microsoft Foundry blog](https://devblogs.microsoft.com/foundry/content-understanding-confidence-grounding-hitl/)
- **Snowflake Document AI**: per-tenant fine-tuning of a model build on reviewed documents, then "Publish version"; fine-tuned `arctic-extract` models stored in a per-org "model registry". — [Snowflake tutorial](https://docs.snowflake.com/user-guide/snowflake-cortex/document-ai/tutorials/create-processing-pipelines); [Snowflake, Working with Document AI](https://docs.snowflake.com/user-guide/snowflake-cortex/document-ai/working-with-document-ai)
- **Trifacta/Alteryx**: the model draws on "user interaction, selected data, historical information, and other sources"; "collaborative suggestions, which aggregate steps used across a workspace"; "the application learns from your selections and prompts you with suggestions based on your previous use." — [Alteryx help](https://help.alteryx.com/aac/en/trifacta-classic/concepts/feature-overviews/overview-of-predictive-transformation.html) (search snippet)
- **Google data insights**: "If you save the table description that Gemini generates, then that description is used to generate future insights"; profile scans ground descriptions, otherwise "the generated column descriptions are based only on the column name." — [Google](https://docs.cloud.google.com/bigquery/docs/data-insights)
- **Google BigQuery data prep by-example**: edit "the values of one to three cells" so Gemini can infer the desired format; "Your example change to the data isn't saved" — i.e., per-session, no persistent learning. — [Google](https://docs.cloud.google.com/bigquery/docs/data-prep-get-suggestions)
- **Databricks Genie Code**: "uses Unity Catalog metadata, table descriptions, lineage, popularity, and example queries to find the right data assets." — [Databricks blog](https://www.databricks.com/blog/announcing-public-preview-lakeflow-designer). Operator descriptions are "AI-generated and editable, and editing one reconfigures the operator to match." — [Databricks docs](https://docs.databricks.com/aws/en/designer/genie-code)
- **Ataccama**: docs describe no learning from accept/reject; suggestions are drawn from the existing rule library and term associations. — [Ataccama](https://docs.ataccama.com/one/latest/data-quality/rule-suggestions.html)
- **Collibra**: no learning described; suggestions recomputed from metadata + profiling per job. — [Collibra](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/ta_suggest-rules.htm)
- **Microsoft Fabric Copilot**: "Copilot doesn't understand previous inputs" — no session memory, no learning. — [Microsoft Learn](https://learn.microsoft.com/en-us/fabric/data-factory/copilot-fabric-data-factory)
- **PROSE/FlashFill**: learning is offline — the ranker was trained once on benchmark tasks; at runtime it is purely example-driven with no persistence. — [Singh & Gulwani 2015](https://www.microsoft.com/en-us/research/publication/predicting-a-correct-program-in-programming-by-example/)

### Inferences
- Cross-tenant learning is Informatica's moat and is explicitly opt-in and anonymized; Oracle's Gen-2 design (publish every integration on the instance) is the most aggressive default. For FORMA's single-tenant/300-customer situation, the analogue is the "other-customer match" in `profile_round` — a within-tenant cross-customer pool.
- The LLM-era products (Fabric Copilot, Glue Q, BigQuery data prep, Palantir Generate) have *less* persistent learning than the ML-era products (Trifacta 2016, Tamr 2019, Informatica CLAIRE 2018). Learning has moved into the metadata layer (catalog descriptions, lineage, example queries) that the LLM reads as context, rather than into model weights.
- Microsoft's refusal to train its confidence model on customer data, paired with a customer-side calibration procedure, is a deliberate trust/privacy trade-off; it is the only vendor documenting it.

### Gaps
- Informatica never documents update cadence, model retraining, or how the "anonymous metadata" is anonymized.
- No vendor documents how rejected suggestions (as opposed to accepted ones) are used as negative signal, except Tamr's generic "accept or reject" feedback.
- No evidence found of a vendor doing per-customer/per-tenant learning of *field mappings* at FORMA's granularity (one source layout per customer, recurring files).

## Key question 5 — What guardrails stop the model from doing harm (sandboxing, dry run, approval gates)?

### Takeaway
The dominant guardrail is architectural: the LLM never has write access to data. It emits an artifact (mapping, step, code, rule) that the platform's deterministic engine executes, under the *user's* identity and permissions, after a preview. Palantir is the most explicit about the limits of this (read-time permissions "do not extend to the model's output or to Ontology edits it composes", so edits can be "staged for human review"); Informatica states agents require a human in the loop before running code or jobs; Collibra's AI "never accesses your actual data rows"; Microsoft Fabric's limitation list and AWS's hallucination warning are the explicit disclaimers.

### Cited Findings
- **Palantir AIP Logic**: "Row and column controls, such as restricted views and object and property security policies, act as read-time enforcement. They filter what the model can read on a user's behalf. These controls do not extend to the model's output or to Ontology edits it composes"; recommends pairing with Markings/CBAC downstream; "Logic functions can be automated so that Ontology edits are either applied automatically or staged for human review." — [Palantir, AIP Logic overview](https://www.palantir.com/docs/foundry/logic/overview/)
- **Palantir Use LLM**: output coerced to a declared type; struct mismatch fails the node; `Include errors` keeps error strings beside values; results cached in a Foundry dataset keyed only on prompt-referenced columns; "Inputs must be deterministic between builds"; cache changes "appear on the Changes page when merging a branch"; a prompt or model change "shows a warning banner"; a platform admin must grant "AIP capabilities for custom workflows". — [Palantir](https://palantir.com/docs/foundry/pipeline-builder/pipeline-builder-llm/)
- **Palantir Evaluation suite**: evaluations run "in an isolated test environment"; needs edit permission on the pipeline. — [Palantir](https://palantir.com/docs/foundry/pipeline-builder/evaluation-suite/)
- **Informatica**: CLAIRE Agents "always require human-in-loop for running any data management code or jobs by default" (product lead, per TechWire Asia, Jun 2025). — [TechWire Asia](https://techwireasia.com/2025/06/how-informatica-claire-agents-are-automating-enterprise-data-tasks/) (search snippet, not fetched). Krish Vitaldevara (CPO): "there's always a human in the loop … Agents can recommend corrections, and you decide whether to apply them and automate them for future use." — [SiliconANGLE, 29 Oct 2025](https://siliconangle.com/?p=718665) (search snippet, not fetched). Analyst summary of the fall 2026 release: "Human-in-the-loop oversight to resolve ambiguity and validate actions"; agents "Execute actions safely with human oversight." — [SoftwareReviews, Mar 2026](https://www.softwarereviews.com/vendor-technology-notes/informatica-introduces-ai-agents-but-does-not-become-an-agentic-ai-platform-yet)
- **Informatica (data path)**: the Copilot output is a mapping asset that goes through normal "save and validate" and runs on the existing engine; the LLM does not execute. — [Informatica, Automapping](https://onlinehelp.informatica.com/IICS/prod/CDI/en/hh-cloud-mappings/Automapping.html)
- **Microsoft Fabric**: tenant admin must enable Copilot; outside US/EU a tenant setting must allow data "processed outside your capacity's geographic region"; trial SKUs unsupported; "AI powers Copilot, so surprises and mistakes are possible"; Copilot "doesn't produce a message for the skills that it doesn't support" (silent failure). — [Microsoft Learn](https://learn.microsoft.com/en-us/fabric/data-factory/copilot-fabric-data-factory)
- **AWS Glue Q**: requires an IAM policy permitting Q code recommendations; "Test and review all code for errors and vulnerabilities before using it"; generated jobs still need manual IAM role attachment before they can run. — [AWS docs](https://docs.aws.amazon.com/glue/latest/dg/q.html); [AWS blog](https://aws.amazon.com/blogs/big-data/amazon-q-data-integration-adds-dataframe-support-and-in-prompt-context-aware-job-creation)
- **AWS SageMaker Canvas**: requires `AmazonSageMakerCanvasAIServicesAccess` policy and explicit Bedrock model access; same-region constraint. — [AWS docs](https://docs.aws.amazon.com/sagemaker/latest/dg/canvas-chat-for-data-prep.html)
- **Google BigQuery data prep**: "During pipeline editing, data and interactions are sent to a Gemini data center for processing"; access via IAM roles, Cloud KMS keys, VPC Service Controls; not supported by Assured Workloads; sample job runs "using your credentials"; Validation steps route bad rows to an error table or fail the run. — [Google](https://docs.cloud.google.com/bigquery/docs/data-prep-introduction)
- **Google data insights**: "Generate without publish" mode avoids writing to the catalog; "Generate and publish" is Preview. — [Google](https://docs.cloud.google.com/bigquery/docs/data-insights)
- **Databricks**: transformations run on Databricks under Unity Catalog governance "from the start"; Genie Code "asks a clarifying question when a request is ambiguous"; proposed prompt fixes are "a diff you approve"; Genie Code can "review its design and cost without making changes"; failed rows "stay visible" and failing documents are "quarantined in a separate table". — [Databricks docs, Designer](https://docs.databricks.com/aws/en/designer/genie-code); [Databricks docs, IDP](https://docs.databricks.com/aws/en/large-language-models/genie-code-document-processing)
- **Snowflake Cortex Code**: actions run under the invoking user's Snowflake role and permissions and "cannot escalate privileges" (third-party characterization). — [Capgemini](https://www.capgemini.com/insights/expert-perspectives/your-new-ai-powered-engineering-partner-inside-snowflake/)
- **Collibra**: "The AI never accesses your actual data rows" (metadata + profiling statistics only); prompts go through "the Collibra AI proxy"; features off unless "AI Rules suggestion" setting is enabled; FedRAMP/self-hosted excluded. — [Collibra suggest rules](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/ta_suggest-rules.htm); [Collibra SQL AI](https://productresources.collibra.com/docs/collibra/2026.08/Content/UnifiedDataQuality/co_about-ai-sql.htm)
- **Ataccama**: AI-based suggestions gated by Global Settings > AI > Gen AI > "Suggest DQ rules"; only users with editing access (Data Owner / Data Steward) can accept; accepted rules apply only after the catalog item is published. — [Ataccama](https://docs.ataccama.com/one/latest/data-quality/rule-suggestions.html)
- **Oracle OIC3**: AI mapping recommendations only "within a project", select regions, limited adapters; per-mapping "Include" checkbox before "Apply". — [Oracle](https://docs.oracle.com/en/cloud/paas/application-integration/mapper-user/generate-mapping-recommendations.html)
- **Microsoft Content Understanding (insurance customer)**: because data is sensitive "reviewers still check every field. Labels direct attention and do not authorize automation"; straight-through processing "Not used in the insurance workflow". — [Microsoft Foundry blog](https://devblogs.microsoft.com/foundry/content-understanding-confidence-grounding-hitl/)
- **Microsoft Dataverse**: preview feature "not meant for production use"; primary key required for updates, else all rows inserted as new. — [Microsoft Learn](https://learn.microsoft.com/power-apps/maker/data-platform/data-platform-import-export)

### Inferences
- No vendor lets an LLM execute arbitrary code against production data in the data path. Even code-generating products (Glue Q, Canvas, Genie Code, Cortex Code) hand the code to the platform's normal runtime under the user's IAM/UC/role permissions; "the model runs as you" is the implicit sandbox.
- Palantir's statement that permissions constrain *reads* but not *outputs* is the clearest articulation of why an output guard (FORMA's `ai/guard.py`) and a policy engine are needed in addition to access control.
- Informatica, Databricks and Palantir all converge on "agent proposes a diff, human approves, approved patterns may then be automated" — the same shape as FORMA's memory-reuse → review → auto-approve path.

### Gaps
- Informatica's human-in-the-loop statements come from press interviews, not product docs; no documentation of a technical dry-run or sandbox for Copilot-generated mappings was found.
- Snowflake's own documentation of Cortex Code's permission model was not located (only Capgemini's description).

## Key question 6 — Published accuracy figures and lessons learned

### Takeaway
Hard numbers are scarce and almost all come from document extraction, not mapping. Microsoft's Content Understanding post is the only vendor source with an evaluation protocol and held-out results (41% fewer values to review while catching >80% of known errors; 97%+ page classification; AUROC +14%). Informatica gives a time claim (7 days → <5 minutes) but no accuracy. Academic LLM schema-matching studies (2024–2025) report ~62% accuracy@1 for the best multi-stage GPT-4 program on medical benchmarks and warn that both too little and too much prompt context hurts.

### Inferences
- The only rigorous public evaluation (Microsoft) shows that even a purpose-built confidence model auto-approves a minority of values at an 80% error-catch target on messy public receipts; the realistic win is *prioritizing* review, not eliminating it. FORMA's eval baseline (identity 1.0, field 0.996) is on synthetic data; the vendors' numbers suggest real-file accuracy will be lower and that the review queue, not auto-approval, is where value accrues.
- Academic results (~62% top-1 on hard medical schema matching) plus the "too much context hurts" finding argue for FORMA's heuristics-first, LLM-fallback design and for feeding the model a curated slice (headers + samples + profile) rather than whole files.
- Analyst consensus is that agentic features across vendors are converging ("catch-up"), and governance (policy + behavioural tracking) is the differentiator — consistent with FORMA rule 6 ("Policy decides, not the model").

### Gaps
- No vendor publishes accuracy for AI *mapping* suggestions (Informatica, Oracle, Dataverse, BigQuery). The 2025 Gartner reprint with per-vendor strengths/cautions could not be fetched (permission denied for the walled copy).
- Matchmaker's exact benchmark numbers come from a search summary of the paper's appendix, not the abstract; verify against the PDF before quoting.
- No public post-mortems or incident reports about AI-generated mappings causing bad data were found.
