# How commercial customer-data-onboarding / CSV-import products use AI to map messy spreadsheets to a target schema, and how they make it reliable

Scope: Flatfile (now "Obvious"), OneSchema, Dromo, Osmos (acquired by Microsoft, Jan 2026), nuvo (now "Ingestro"), Flatirons Fuse (now Swovo), CSVBox, Impler, Tiny Importer, plus two independent engineering write-ups and adjacent patents. Research date: 2026-11-02. Material is 2023–2026 unless marked older. Where a fact comes from a search-engine snippet rather than a fetched page it is marked "(snippet)".

Vendor-renames that matter when reading sources: Flatfile rebranded to **Obvious** in 2025 (Flatfile remains the importer product; USPTO filing for OBVIOUS dated 2025-10-08) — [ai.engineer profile](https://ai.engineer/orgs/flatfile), [trademark record](https://markinton.com/trademark/obvious-99432724), [Dromo commentary](https://dromo.io/blog/what-happened-to-the-flatfile-importer). nuvo → **Ingestro** (docs.getnuvo.com 301-redirects to docs.ingestro.com; getnuvo.com blog redirects to ingestro.com) — [docs.ingestro.com](https://docs.ingestro.com/sdk/overview). Flatirons Fuse → **Swovo** (flatirons.com blog 301-redirects to swovo.com) — [swovo.com](https://swovo.com/blog/introducing-smart-mapping/). Osmos → Microsoft, standalone products being sunset — [Redmond Mag, 2026-01-06](https://redmondmag.com/Articles/2026/01/06/Microsoft-Acquires-Osmos-To-Bring-Autonomous-Data-Engineering-to-Fabric.aspx).

## Key Question 1 — For each product: what does the AI do, what inputs does it see, how is its output verified, where does the human come in?

### Takeaway
Every product layers deterministic matching (exact/normalised header match, developer-declared aliases, per-sender history) in front of an ML/LLM "semantic" layer; the AI is used for the residual columns only and its result is always rendered in a mapping UI for human confirmation unless an explicit "skip/headless" setting is turned on. Only Flatfile's legacy docs state that the ML model sees *values*; Dromo and Ingestro describe matching on header text (label/key/aliases), and Dromo's AI Transform explicitly never sees row data.

### Cited Findings

**Flatfile / Obvious**
- Mapping is split into "Field mapping" (source column → destination field) and "Enum mapping" (source value → allowed enum value, e.g. "United States" → "US"); suggestions come from "machine-learning models trained on millions of historical mappings" and are based on "the column names and values in the source data"; users "can of course override these suggestions" — [Flatfile legacy mapping concepts](https://flatfile.com/docs/legacy-docs/concepts/mapping.md) (flagged as legacy docs).
- Support article: a model trained on "1.8 billion (and counting!) rows processed in Flatfile", combined with "memory of past selections", can "accurately predict over 90% of matching actions"; predicted mappings are applied automatically "reducing the number of mapping actions we ask you to make" — [Flatfile support: Mapping Data](https://support.flatfile.com/articles/8569925090-mapping-data).
- Marketing page: engine "trained on 5B+ mapping decisions", "gets smarter every import", can "learn from past imports" — [flatfile.com/product/mapping](https://flatfile.com/product/mapping/). About page: "95% of fields are auto-mapped using AI", "4.7x faster data onboarding vs. manual processes", "78% of customers go live within 30 days" — [flatfile.com/about](https://flatfile.com/about/). Note the training-size figures are inconsistent across Flatfile pages (1.8B rows vs. "millions of historical mappings" vs. "5B+ mapping decisions"); treat as marketing.
- Human step: "Map Fields" page lists suggested mappings; a round-arrow control clears all suggestions ("Think we got it wrong?"); unmapped fields pick a destination from a dropdown; hovering a field shows a data preview; "Add as New Field" creates a new review-table column; "Any source fields that are not mapped to a destination field will be excluded from the import." Option (enum) fields open a separate value-mapping screen with "Keep this value as is" (unmatched values then error in the review table) and "Do not import" (blank cell, column still imported) — [Flatfile support: Mapping Data](https://support.flatfile.com/articles/8569925090-mapping-data).
- Mapping output is a machine-readable **execution plan** on the mapping job: `plan.fieldMapping[]` entries each carry `sourceField {key,type}`, `destinationField {key,type,label,constraints}`, a `preview` list of sample values, and `metadata {certainty, source}`; plus `plan.unmappedSourceFields[]` (with previews) and `plan.unmappedDestinationFields[]`. The support example shows `"certainty": "strong"` and `source` values that are user IDs — [Flatfile support: Retrieve Mapping Information](https://support.flatfile.com/en/articles/8148440-retrieve-mapping-information). The API reference example shows `"certainty": "absolute", "confidence": 1` and the plan can be replaced with `PUT /v1/jobs/:jobId/plan` — [Flatfile API: update execution plan](https://reference.flatfile.com/api-reference/jobs/update-execution-plan) (snippet).
- Programmatic mapping: `@flatfile/mapping` (TS) expresses every transformation as a `MappingRule` object (assign, concatenate with separator; rules can carry an FFQL `filter`) — [pkgstats @flatfile/mapping](https://www.pkgstats.com/pkg:@flatfile/mapping) (snippet). Python `flatfile-mapping` ("extreme beta") supports assign, subprogram, nest, constant; "Rules are intended to be applied in order, and the results of earlier rules can be used by (or overwritten by) later rules"; with a secret key it exposes automapping that currently emits `assign` and `ignore` rules — [pypi flatfile-mapping](https://pypi.org/project/flatfile-mapping/), [legacy mapping concepts](https://flatfile.com/docs/legacy-docs/concepts/mapping.md). Legacy docs: the Flatfile app itself "only supports the `assign` rule type"; planned: AI suggestions for complex rules (concatenation) and a natural-language interface for creating mapping rules — same source.

**OneSchema**
- Base matching: "In addition to mapping columns that have exact column names, OneSchema will also remember historical mappings that your users may have successfully imported in the past" — [OneSchema changelog: intelligent column mapping](https://docs.oneschema.co/changelog/intelligent-column-mapping) (undated).
- AI layer: "You can now leverage AI for helping with mapping columns and picklists"; "1-click mode" = "drag and drop any file and OneSchema will automatically map and apply any transformations to the uploaded file"; out of beta for all customers — [OneSchema changelog: AI-suggested mappings and 1-click mode](https://docs.oneschema.co/changelog/ai-suggested-mappings-and-1-click-mode-are-now-public) (undated).
- Newer agentic layer: "Set Columns Agent" "suggests matches automatically, explains its reasoning, and lets you refine mappings through conversation before applying them", aimed at "files [that] have ambiguous or inconsistently named columns" (screenshot filename dated 2026-06-30) — [OneSchema changelog: set columns agent](https://docs.oneschema.co/changelog/set-columns-agent).
- Developer-declared hints: `mapping_hints` = "Array of sheet column names to automatically map this column to" (per-customer template overrides); picklist `alternative_names`: "If uploaded values match any of the alternative names, the picklist option will be matched automatically" — [OneSchema docs: per-customer template overrides](https://docs.oneschema.co/docs/per-customer-overrides-v2).
- FileFeeds (recurring, headless): "Show an agent a sample file and it infers the right transform (header detection, column mapping, value cleanup, taxonomy classification, error fixes) without step-by-step prompts"; it "pulls your team in for the rows or fields it can't confidently handle"; each row is "checked against a OneSchema Template" ("50+ built-in validations", custom code hooks); every agent action appears in a "transparent, observable run history" — [OneSchema docs: Getting started with Multi FileFeeds](https://docs.oneschema.co/docs/getting-started-filefeeds).
- Billing signal that AI is metered: "AI Credits Usage Dashboard", April 2026 — [oneschema.co/changelog](https://oneschema.co/changelog) (snippet).

**Dromo**
- Matching inputs: "Dromo will try to match columns headers in the user data to a corresponding `label` or `key`"; `alternateMatches: string[]` adds aliases (e.g. `["municipality","town","locality"]` for `city`); "Column matching is case-sensitive"; `description` is display-only (not used for matching); `requireMapping` blocks continuing until matched; `hidden` fields cannot be matched; `selectOptions[].alternateMatches` for picklist values — [Dromo fields reference](https://developer.dromo.io/fields.md).
- `matchingStep.fuzzyMatchHeaders` (default `true`): "Determines whether Dromo will use fuzzy matching to suggest column mappings"; when `false`, suggestions require an exact match to `label`, `key`, or `alternateMatches`. `matchingStep.matchToSchema` (default `false`) flips the UI to map schema fields → file columns. `allowCustomFields`, `passThroughUnmappedColumns` (`$unmapped`) — [Dromo settings reference](https://developer.dromo.io/reference/settings/settings.md).
- AI engine: changelog v1.8.0 (Feb 2023) "Improved AI Column Matching: Smarter automatic field detection and mapping"; v2.0.5 (May 2023) "Schema-based Column Matching" — [Dromo developer changelog](https://developer.dromo.io/changelog.md). Blog (2025-04-04): "GPT-driven column matching to automatically map imported data to your schema", handling "variations in header names, synonyms, and context"; "one-click mapping for most files" — [Dromo blog: How AI is transforming data imports](https://dromo.io/blog/how-ai-is-transforming-data-imports-and-validation). Blog (2025-09-24): "uses intelligent algorithms (including GPT-3/4 language models)"; "analyzes the header labels (and even samples of the data)"; "Every column is either confidently auto-matched or explicitly reviewed by the user"; claims "reduce onboarding errors by up to 98%" and 5–10× faster onboarding (vendor claims, unverified) — [Dromo blog: Improving data import accuracy](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching). Contradiction: the Sept-2025 blog says samples of data are analysed; the Apr-2025 blog says the (transform) AI "operates without direct access to raw data (to maintain privacy)"; the official docs name only label/key/alternateMatches. Treat "samples of the data" as unconfirmed.
- Human step: unmatched columns prompt the user "to map it via an intuitive interface rather than the import failing"; after mapping, validation runs on every cell "flagging any format or type errors to the user before the import is finalized" — [Dromo blog, Sept 2025](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching).
- `reviewStep.highlightAutoFixes` (default `false`) highlights "cells changed by automatic transformations, such as rounded numbers or select values changed from alternate matches" — [Dromo settings](https://developer.dromo.io/reference/settings/settings.md).

**Osmos** (docs on 42layers.gitbook.io; pages redirect to app.gitbook.com and could not be fetched — all Osmos doc facts are snippets)
- "AutoMap" links uploaded headers/columns to the destination schema, "runs on generative AI", and the UI marks in the top-right corner when it was triggered; the mapping panel has one card per destination column and lets you connect one or more uploaded columns to each — [Osmos Uploader: automapping](https://42layers.gitbook.io/uploader/automapping) (snippet). Examples: "MSRP" → "Price", "Vehicle Identification Number" → "VIN" — [Osmos Data Transformations guide](https://42layers.gitbook.io/data-transformations/column-mapping-and-data-cleanup-panel) (snippet).
- "AutoClean" = one-click cleanup; prebuilt rules; developers can write their own AutoClean functions; for enum fields "valid options are set in validation, and AutoClean handles mapping the incoming values to them. Values that match nothing stay unchanged and raise an error"; AutoClean runs **before** the server-side validation webhook, which "can return final values, errors, or warnings"; fields can be excluded; not available in Advanced Mode — [Osmos AutoClean](https://42layers.gitbook.io/uploader/standard-mode/autoclean), [Configuring AutoClean](https://42layers.gitbook.io/developer-docs/configuring-autoclean-for-your-uploader) (snippets).
- 2023 approach (older): Osmos "applies AI to the transformation logic rather than to the data directly"; users "supply a few example rows of the desired output, and the system generates a debuggable transformation program"; users correct errors "with more examples or formulas, and the system learns from those fixes"; CEO Kirat Pandya: "The issue with most AI today is that it's a black box"; GPT-4 announcement 2023-04-03 — [syndicated press release](https://journalofcyberpolicy.com/?p=105190) (snippet; page returned 404 on fetch).
- 2025–26 direction: "AI Data Wrangler" "learns from your data, adapts to unique formats, and outputs SQL-ready data—no rules, templates, or code required"; "AI Data Engineer" generates/validates PySpark notebooks in Microsoft Fabric; Microsoft acquisition Jan 2026, standalone products to be sunset — [Campus Technology 2026-01-12](https://campustechnology.com/articles/2026/01/12/microsoft-acquires-osmos-for-agentic-ai-data-engineering.aspx), [Redmond Mag](https://redmondmag.com/Articles/2026/01/06/Microsoft-Acquires-Osmos-To-Bring-Autonomous-Data-Engineering-to-Fabric.aspx).

**nuvo / Ingestro** — the most explicitly documented pipeline
- Match step: "Our Ingestro AI restructures the data and matches the imported columns to the columns in your defined output schema"; users confirm recommended matches or create new mappings; "It learns from initial imports, so if a similar file structure is uploaded in the future, this step can be skipped" — [Ingestro SDK overview](https://docs.ingestro.com/sdk/overview).
- `columnMappingConfiguration.layers`, default `["exact", "historic", "smart", "fuzzy"]`, applied "exact matches first, then historical patterns, followed by AI-powered matching, and finally, fuzzy matching"; `exact` = "Finds exact matches only" (ignores special characters and case); `historic` = mappings from previous imports; `smart` = "Uses our Ingestro AI for mapping"; `fuzzy` = "Identifies partial text similarities"; `smart` and `historic` are unavailable when `processingMode: "browser"` (default `"node"` = server) — [Ingestro SDK settings](https://docs.ingestro.com/sdk/settings).
- Inputs: column matching uses `key`, `label`, and `alternativeMatches` ("every item of the `alternativeMatches` array is considered" in the similarity calculation; recommended content: "abbreviations and synonyms"); option mapping uses `label` and `alternativeMatches` only; the algorithm is described as machine learning with a logic-based component; `description` is display-only — [Ingestro SDK columns](https://docs.ingestro.com/sdk/columns). The docs do **not** list sample values as a matching input.
- Dropdown values: AI "extends to dropdown options", requires processing engine `node` — [nuvo product update Dec 2023](https://getnuvo.com/blog/product-update-december-2023) (snippet). `optionMappingConfiguration.layers` default `["exact","fuzzy"]` with `historic`/`smart` optional, `threshold` default 0.6 — [Ingestro SDK columns](https://docs.ingestro.com/sdk/columns).
- Human step: Review step where users "fix errors manually or use Ingestro AI for data cleaning"; `requireConfirmation: true` forces the mapping step to always show, pre-filled — [Ingestro SDK overview](https://docs.ingestro.com/sdk/overview), [settings](https://docs.ingestro.com/sdk/settings).

**Flatirons Fuse (Swovo)**
- "Smart Mapping" (2024-01-06): "Fuse harnesses the capabilities of OpenAI to automatically match columns from your uploaded CSV into the importer"; "Fuse goes a step further by remembering the column mappings used in that import" and "automatically applies the previously used column mappings" on later similar imports. No model named, no statement on whether row data is sent, no confidence or accuracy figures — [Swovo blog: Introducing Smart Mapping](https://swovo.com/blog/introducing-smart-mapping/).

**CSVBox**
- Declared aliases: "Matching Keywords" are "alternative matching options to help users match column names automatically" (e.g. `F_Name`, `First` for `First Name`); "CSVbox auto-maps columns via continuous learning": the importer "remembers the columns mapped by users" and accumulates "User Keywords"; these can be viewed/deleted in Column Settings and switched off via Sheets → Options → "User Keywords for Column Mapping" — [CSVbox help: Column Options](https://help.csvbox.io/dashboard-settings/sheet-options).
- Vendor explainer (dated 2026-08-01) describes a four-layer cascade: exact → normalised (case/punctuation/accents/BOM) → fuzzy (Levenshtein or Jaro-Winkler + token-set overlap) → semantic ("embeddings or an LLM compare meaning rather than characters"); "CSVbox runs this cascade automatically"; three tiers: High = auto-applied, Medium = pre-filled but flagged for confirmation, Low = left unmapped; "Never auto-apply a low-confidence match silently"; example fuzzy threshold 0.87; recommends checking candidates against ~20 sample values — [CSVbox: AI column mapping](https://csvbox.io/resources/ai-column-mapping). Caveat: this is marketing/explainer content; the official help pages do not mention an AI layer or confidence tiers.
- "AI Pre-Import Transform": a per-sheet plain-English prompt that restructures files (rename columns, flatten headers, reorder rows, split/merge) **at upload, before column mapping**; "The transformed result is what the user sees in the column-mapping step"; the AI "follows the instruction exactly as written"; if it cannot apply the transform "the original data is shown unchanged"; complex logic "may fall back to a direct AI call" (vs. a cheaper "recipe"); credits = 1 per 1,000 tokens, flat 1 credit for an unchanged re-upload — [CSVbox help: AI Pre-Import Transform](https://help.csvbox.io/dashboard-settings/ai-pre-import-transform).

**Impler**
- Open-source import widget: "Users can map columns and even review invalid records in their spreadsheets" — [Impler docs README](https://github.com/implerhq/docs/blob/main/README.md). Docs index lists Base/Advanced/Custom Validations ("Write your own validation code… checks against external databases or APIs"), "Automated Import" ("automate data import from remote locations"), "Runtime Schema" — [docs.impler.io/llms.txt](https://docs.impler.io/llms.txt). No page on AI or automatic column matching was found.

**Tiny Importer** — no product by this name surfaced in any search (results returned Dromo, Fuse, CSVbox, ClickUp instead). Not confirmed to exist.

### Inferences
- The industry-standard shape is a **cascade**: exact → declared aliases → per-sender history → ML/LLM → fuzzy, with the AI covering only the residual. Ingestro documents this literally as `layers`; CSVbox describes the same; Flatfile and OneSchema describe exact + history + model.
- "The model sees values" is the exception, not the rule: only Flatfile's (legacy) docs say so; Dromo's and Ingestro's reference docs describe header-text inputs; Dromo's transform AI explicitly receives no data. Products lean on *developer-declared aliases* and *history* rather than value inspection for disambiguation.
- Picklist/enum value mapping is treated as a second, parallel matching problem with the same mechanics (aliases + history + AI) in Flatfile, OneSchema, Dromo, Ingestro, Osmos.

### Gaps
- No vendor publishes the model type (embedding vs. fine-tuned classifier vs. LLM prompt) for column matching except Dromo's "GPT-3/4" and Fuse's "OpenAI" mentions. Flatfile's "trained model" is not described further.
- Osmos documentation pages could not be fetched (GitBook redirect); facts are from search snippets only.
- Impler: no AI mapping found; Tiny Importer: not found.

## Key Question 2 — Which products run the generated mapping/transform on sample rows and feed results back to the model or to the user before commit?

### Takeaway
All products with AI transforms show a **preview** of the transformed data to the user before applying (Flatfile AI Assist, Dromo Transform Data, OneSchema FileFeeds sample file); only Osmos (2023) describes feeding user corrections back to regenerate the program, and no vendor documents an automated model-self-check loop on sample output.

### Cited Findings
- Flatfile AI Assist (docs call it AI Assist; marketing calls it AI Transform): "Use AI Assist to describe the transformations you need, and watch as your data is instantly updated"; "Preview the changes AI Assist will make before applying them to ensure accuracy"; "Refine your prompts and see instant updates to your data in the preview mode"; "Keep a snapshot of your data before each change, allowing you to revert to previous versions if needed"; commands can be scoped with filters to "only the selected records"; "Your data is not shared with third-party AI providers", "all processing done within Flatfile's infrastructure"; Pro/Enterprise only; multi-language prompts (French example) — [Flatfile docs: AI transformations](https://flatfile.com/docs/guides/ai-transformations). Flatfile "turns these commands into code and makes the desired changes instantly across your entire data set" — [Flatfile 2024 year in review](https://flatfile.com/blog/2024-flatfile-year-in-review/) (snippet).
- Flatfile Transform (July 2025, "agentic"): the agent "reviews each record against validation rules and past user decisions, then suggests transforms that can be applied with a click"; "Users can also prompt transforms directly from any field, or refine AI suggestions inline"; "every agent action is surfaced for human review and tracked in version history" — [Flatfile news: Transform](https://flatfile.com/news/flatfile-announces-transform-an-advanced-agentic-experience-for-data/) (snippet), [Flatfile system integrators page](https://flatfile.com/solutions/system-integrators/) (snippet).
- Dromo "Transform Data" (v3.2.0, Oct 2024): "takes a user's request and turns it in to a transformation that can be applied to the data"; "the AI building the transformation function"; "If a transformation is produced, the result is previewed so the user can accept or reject it"; limits: can edit values and remove rows but "cannot add rows"; row-at-a-time only (cannot use other rows or external data); "The AI never sees the import data", so prompts must state current and target formats (good: "Change the date format from 'Jul-8-1999' to MM-DD-YYYY"; bad: "Change the dates to US format"); request + "some schema information" goes to OpenAI, "absolutely no user data is transmitted"; Pro plan; `reviewStep.transformDataPrompts` (v3.13.0, June 2026) supplies canned prompt suggestions — [Dromo guide: Transform Data](https://developer.dromo.io/guides/using-transform-data.md), [Dromo changelog](https://developer.dromo.io/changelog.md). Blog: "The model generates a transformation function, previews the results to the user"; users "encouraged to include context like sample input-output pairs in their requests" — [Dromo blog Apr 2025](https://dromo.io/blog/how-ai-is-transforming-data-imports-and-validation).
- Dromo "AI-Powered Hook Generator" (v3.9.0, March 2026) "lets users generate hook code from a plain-language prompt" (developer-side code generation, not end-user) — [Dromo changelog](https://developer.dromo.io/changelog.md).
- OneSchema FileFeeds: transforms are authored "visually, by recording example edits, or from natural-language instructions"; the agent infers from a **sample file**; uploading a new sample file auto-opens the column-mapping modal and matched columns show a green "MAPPED" badge; "All saved transforms will run on uploaded documents in order"; custom JS/TS code actions in two categories — "Data Setup actions run before template mapping. Transforms run after mapping" — [OneSchema FileFeeds getting started](https://docs.oneschema.co/docs/getting-started-filefeeds), [FileFeeds mapping/transforms updates](https://docs.oneschema.co/changelog/filefeeds-mapping-transforms-experience-updates), [FileFeed transforms & code actions](https://docs.oneschema.co/docs/filefeeds-transformations-codeactions). AI Transforms: from an error choose "Apply a transform using AI" or Transforms → Add transform → "Create a custom transformation with AI", type e.g. "delete rows where TAXNO is empty"; "This adds a step to your transformation pipeline, and this step is not shareable with other FileFeeds" — [OneSchema changelog: FileFeeds AI transforms](https://docs.oneschema.co/changelog/filefeeds-ai-transforms). The representation of the generated step (code vs. rule) is not documented.
- Osmos (2023, older): example rows in → "debuggable transformation program" out; corrections via more examples/formulas; "the system learns from those fixes" — [press release syndication](https://journalofcyberpolicy.com/?p=105190) (snippet).
- Adjacent (not an importer): Zoho DataPrep "Transform by Example" uses a ChatGPT-generated formula and "retries the query when the output doesn't match" the user's examples — [Zoho DataPrep help](https://help.zoho.com/portal/en/kb/dataprep-2-0/data-transformation/data-transforms/transform-by-example-using-chatgpt/articles/transform-by-example-powered-by-openai-chatgpt-api) (snippet).
- Independent practitioner pattern: LLM receives "50-100 rows, the target schema, and a list of allowed operations" and returns an ordered declarative plan (JSON config of rename / map_values / split_name / filter / convert); execution is plain pandas ("Same input always produces same output"); a Pydantic model is the success criterion; four gates (schema, shape, distribution, business logic) run before DB writes; a failed gate yields a report (e.g. "45% of addresses didn't geocode") that is fed back to the agent for plan revision — [dev.to: AI data cleaning in production](https://dev.to/potapov/ai-data-cleaning-in-production-from-toy-demos-to-real-pipelines-m17).

### Inferences
- The commercial pattern is **generate → execute on the real dataset → show diff/preview → human accepts**, with undo via snapshot/version history. The "feed results back to the model" loop appears only in Osmos's 2023 PBE design and in independent write-ups, not in current Flatfile/Dromo/OneSchema docs.
- Dromo's choice to withhold all row data from the LLM shifts the burden onto the user to specify formats; Flatfile avoids the privacy problem by hosting the model in-house and letting it see data.

### Gaps
- Whether Flatfile AI Assist or OneSchema AI Transforms produce code (JS/Python) vs. a declarative rule is not documented; Flatfile's year-in-review says "code" (snippet) without detail.
- No vendor documents running the generated transform on a sample and checking it against validations automatically before showing it.

## Key Question 3 — How is confidence computed and used for routing (auto-map vs. review)?

### Takeaway
Confidence surfaces as either a numeric 0–1 threshold on a similarity score (Ingestro default 0.6) or coarse certainty bands (Flatfile `absolute` = 100%, `strong` > 90%); routing is all-or-nothing at the file level in headless modes (Flatfile automap aborts the whole job if one column is below threshold; Dromo headless goes to `NEEDS_REVIEW` if any column cannot be mapped), while interactive modes simply pre-fill and let the user confirm. No vendor explains how the underlying score is computed.

### Cited Findings
- Flatfile `@flatfile/plugin-automap`: "determines whether to proceed with the mapping based on a configurable confidence level"; `accuracy: 'confident'` → "All mapped fields must have a confidence level of 'strong' (> 90%) or 'absolute' (100%)"; `accuracy: 'exact'` → "All mapped fields must have a confidence level of 'absolute' (100%)"; "The `accuracy` check is all-or-nothing" — one low column aborts the job; `onFailure` callback for notification/alternative handling; `matchFilename` RegExp limits which files are auto-mapped; `defaultTargetSheet` string or function of filename; the plugin renames the file with a status marker during processing — [Flatfile automap plugin docs](https://flatfile.com/docs/plugins/automap.md). Plan metadata exposes `certainty` and numeric `confidence` (`"absolute"`, `1`) — [Flatfile API update execution plan](https://reference.flatfile.com/api-reference/jobs/update-execution-plan) (snippet); "strong" appears in the support example — [Retrieve Mapping Information](https://support.flatfile.com/en/articles/8148440-retrieve-mapping-information).
- Ingestro: `columnMappingConfiguration.threshold` "The default is 0.6 (60%)", 0–1, "minimum match confidence"; lower = more matches, higher = stricter; same for `optionMappingConfiguration.threshold` (0.6) — [Ingestro settings](https://docs.ingestro.com/sdk/settings), [columns](https://docs.ingestro.com/sdk/columns). Mapping step is skipped only if "all required target columns are mapped" and every mapped date column has a date format; `applyColumnMapping` / `applyOptionMapping`: `'none'` | `'gapFill'` (auto-matching only fills gaps after a saved mapping is applied) | `'always'`; `requireConfirmation` always shows the pre-filled step — [Ingestro settings](https://docs.ingestro.com/sdk/settings).
- Dromo headless: `SUCCESSFUL` if no issues; `NEEDS_REVIEW` when "The header row could not be determined", "The columns could not be mapped automatically", or validations fail with `invalidDataBehavior: BLOCK_SUBMIT`; `FAILED` for corrupt/empty files or a throwing hook; a `review_url` opens Dromo's import UI to resolve, after which status becomes `SUCCESSFUL`; no documented `NEEDS_REVIEW` webhook event (only `import_completed`); rate limits 20 creates/min, 12 polls/min/import — [Dromo headless quickstart](https://developer.dromo.io/getting-started/headless.md). Interactive: "Every column is either confidently auto-matched or explicitly reviewed by the user" (no thresholds given) — [Dromo blog Sept 2025](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching). Column matching step is skipped entirely when all columns exactly match key/label/alternateMatches of every field (v1.7.0, June 2022, older) — [Dromo changelog](https://developer.dromo.io/changelog.md).
- OneSchema FileFeeds: agent "pulls your team in for the rows or fields it can't confidently handle" — [FileFeeds getting started](https://docs.oneschema.co/docs/getting-started-filefeeds). No numeric confidence documented.
- CSVbox explainer: High/Medium/Low tiers → auto-apply / pre-fill+flag / leave unmapped; example fuzzy threshold 0.87; "tune thresholds against real customer headers rather than using a universal number" — [CSVbox: AI column mapping](https://csvbox.io/resources/ai-column-mapping) (vendor explainer, not reference docs).
- Independent: Catalogit mapper combines three cosine-similarity queries per column (header, value, context) with weights ("header dominates, context refines, value disambiguates"), a "type-compatibility multiplier" that "softly penalizes implausible matches, such as a date column mapping to a URL field", and a "structural-constraint filter" that removes candidates that cannot hold the column's shape; historical mappings above a "high-similarity threshold" bypass AI; "Over 85% of suggestions accepted" — [Catalogit CSV schema mapper write-up](https://dchoiboi00.github.io/projects/csv-schema-mapper-at-catalogit). Potapov: regex parsing first with a score; ~80% high-confidence skip the LLM; low-confidence go to the LLM; unresolved flagged for human review — [dev.to](https://dev.to/potapov/ai-data-cleaning-in-production-from-toy-demos-to-real-pipelines-m17).

### Inferences
- "Confidence" in these products is a property of the *matcher layer that fired* as much as a number: exact/history hits are treated as certain, AI/fuzzy hits as needing confirmation. Flatfile's `absolute`/`strong` bands and Ingestro's layer order both encode this.
- For unattended (recurring) files, vendors choose file-level all-or-nothing gating plus a human review URL rather than partial auto-commit — nothing partial becomes visible.

### Gaps
- No vendor documents how the numeric score is produced (string similarity, embedding cosine, model logit) or how the per-column score aggregates to the `strong`/`absolute` band.
- Flatfile docs do not state what range maps to anything below "strong" (a "weak" band is implied but not documented).

## Key Question 4 — How do they remember mappings per customer/sender and detect when a file layout changed?

### Takeaway
Memory is keyed on a **fingerprint of the source column set plus the target schema** (Ingestro "scenario identifier"), on a developer-supplied **sender identifier** (Dromo `importIdentifier` with `autoMapHeaders`), or on user/workspace history (Flatfile, OneSchema, CSVbox "User Keywords", Osmos "recall at the uploader level"). Layout change is detected implicitly: the fingerprint no longer matches, so the saved mapping does not apply and the file falls back to AI/manual matching or, in headless modes, to a review state; no vendor documents explicit drift scoring or alerts.

### Cited Findings
- Ingestro: saved mappings "are tied to a scenario identifier, a fingerprint of the source columns and target structure"; "The saved mapping is looked up from the browser's local storage first, then from the remote API"; "Option mappings, unlike column mappings, may contain sensitive data" and are saved server-side only when `automaticMapping` is enabled; deprecated `automaticMapping` scenario matching "depends on the column headers, each column's `key` and `isMultiSelect`, and each dropdown option's `value`. If any differ, automatic mapping is not triggered"; `skipConfiguration.mapping.automaticMapping` reuses saved mappings "when the same data structure appears again"; `'gapFill'` lets auto-matching fill only the columns the saved mapping does not cover (i.e. new columns) — [Ingestro settings](https://docs.ingestro.com/sdk/settings).
- Dromo: `autoMapHeaders` (default `false`; "Remember mapped headers and values", v3.0.5 June 2024) requires `backendSyncMode` `"MAPPINGS_ONLY"` or `"FULL_DATA"`; "Dromo will try to automatically map the CSV headers to fields" using earlier uploads with the same `importIdentifier`; users can still change the mapping; in `MAPPINGS_ONLY` "only the column mapping and unique values from 'select' type fields will be stored in our backend" — [Dromo settings](https://developer.dromo.io/reference/settings/settings.md), [changelog](https://developer.dromo.io/changelog.md). Blog: `autoMapHeaders` "will remember how a given client or dataset mapped their columns in a previous import" — [Dromo blog Sept 2025](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching).
- Flatfile: "remembers your previously chosen mappings and will suggest them" when it sees similar schemas or data later — [legacy mapping concepts](https://flatfile.com/docs/legacy-docs/concepts/mapping.md); model "learns from both your and your colleagues' earlier selections" — [support: Mapping Data](https://support.flatfile.com/articles/8569925090-mapping-data) (snippet); plan `metadata.source` records user IDs of who made a mapping — [Retrieve Mapping Information](https://support.flatfile.com/en/articles/8148440-retrieve-mapping-information).
- OneSchema: remembers "historical mappings that your users may have successfully imported in the past" — [intelligent column mapping](https://docs.oneschema.co/changelog/intelligent-column-mapping); per-customer `templateOverrides` with `mapping_hints` and picklist `alternative_names`, passed per embed session (`clientId`, `userJwt`, `templateKey`) — [per-customer overrides](https://docs.oneschema.co/docs/per-customer-overrides-v2). FileFeeds: one feed per recurring source (SFTP/S3/GCS), transform graph version-controlled ("every change to a Multi FileFeed is reviewable and reversible"), "FileFeeds now respect pushed templates (relying on the latest template version pushed to the Production environment)", bulk action "Add all missing columns" when the feed lacks template columns, "Remove unmapped columns" available in Sheet Transforms, runs with "Error rows remaining" can be opened with "Manually fix errors" into the Importer's "Review & finalize" UI — [FileFeeds getting started](https://docs.oneschema.co/docs/getting-started-filefeeds), [FileFeeds mapping/transforms updates](https://docs.oneschema.co/changelog/filefeeds-mapping-transforms-experience-updates), [remove unmapped columns](https://docs.oneschema.co/changelog/remove-unmapped-columns-in-sheet-transforms), [oneschema.co/changelog](https://www.oneschema.co/changelog) (snippet).
- CSVbox: "remembers the columns mapped by users" as "User Keywords" accumulated per sheet, viewable/deletable, toggle "User Keywords for Column Mapping" — [CSVbox Column Options](https://help.csvbox.io/dashboard-settings/sheet-options).
- Osmos: "On first upload, fields are mapped manually or through AI. On later uploads, mappings are recalled at the uploader level. For internal uploaders, an admin feature flag sets the baseline recall behavior" — [Osmos automapping](https://42layers.gitbook.io/uploader/automapping) (snippet).
- Fuse/Swovo: remembers mappings and "automatically applies the previously used column mappings" for later imports with similar column structures — [Swovo Smart Mapping](https://swovo.com/blog/introducing-smart-mapping/).
- ClickUp (adjacent): "uses historical mappings of files of the same structure and AI to pre-map columns to fields" — [ClickUp feedback page](https://feedback.clickup.com/feature-requests/p/import-csv-and-map-to-existing-fields) (snippet).
- Independent: per-source config reused with "no LLM call" on repeat deliveries in the same format — [dev.to](https://dev.to/potapov/ai-data-cleaning-in-production-from-toy-demos-to-real-pipelines-m17); "Synthetic (internal) columns always resolve from history. Historical mappings above the similarity threshold bypass the AI. AI suggestions fill remaining gaps"; "If the AI step fails or times out, the import falls back to historical-only mappings rather than blocking" — [Catalogit](https://dchoiboi00.github.io/projects/csv-schema-mapper-at-catalogit).

### Inferences
- Two memory scopes coexist: *structural* (fingerprint of headers → exact replay, Ingestro/Dromo) and *statistical* (header→field pairs across many users feeding the model, Flatfile/CSVbox). Products that do the former get deterministic "skip the step" behaviour; the latter improves suggestions but still needs confirmation.
- Drift handling is "fail closed": a changed fingerprint simply disables replay; `gapFill` (Ingestro) is the only documented *partial replay* mode (keep what still matches, AI the new columns).
- Option/value mappings are treated as more sensitive than column mappings (Ingestro stores them server-side only on opt-in; Dromo `MAPPINGS_ONLY` stores select unique values).

### Gaps
- No vendor documents an explicit "layout changed" signal, drift score, or notification; detection is inferred from fallback behaviour.
- OneSchema's handling of a *new* column appearing in a recurring FileFeed (ignored? error? review?) is not documented beyond the "Remove unmapped columns" transform and the mapping modal on sample re-upload.

## Key Question 5 — What do they say about learning from user corrections (fine-tuning, few-shot memory, per-workspace models)?

### Takeaway
Vendors claim learning but describe only two concrete mechanisms: (1) storing the confirmed mapping as history/aliases that replay or bias future matches (all vendors), and (2) a shared model trained on aggregated mapping decisions across all customers (Flatfile only). No vendor documents fine-tuning per workspace or few-shot prompting with a customer's past corrections.

### Cited Findings
- Flatfile: model "trained on mapping choices from 1.8 billion (and counting!) rows processed in Flatfile" and "learns from both your and your colleagues' earlier selections" — [support: Mapping Data](https://support.flatfile.com/articles/8569925090-mapping-data); "5B+ mapping decisions", "learn from past imports" — [product/mapping](https://flatfile.com/product/mapping/); Transform agent reviews records "against validation rules and past user decisions" — [Transform news](https://flatfile.com/news/flatfile-announces-transform-an-advanced-agentic-experience-for-data/) (snippet).
- Dromo: "learn from common header variations over time" (blog) and per-`importIdentifier` replay (`autoMapHeaders`) — [Dromo blog Sept 2025](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching), [settings](https://developer.dromo.io/reference/settings/settings.md).
- Ingestro: `historic` layer "Uses mappings from previous imports"; "It learns from initial imports" — [settings](https://docs.ingestro.com/sdk/settings), [overview](https://docs.ingestro.com/sdk/overview).
- CSVbox: "continuous learning" = User Keywords collected from user mappings — [Column Options](https://help.csvbox.io/dashboard-settings/sheet-options).
- OneSchema: historical mappings remembered; Set Columns Agent lets users "refine mappings through conversation before applying them" — [intelligent column mapping](https://docs.oneschema.co/changelog/intelligent-column-mapping), [set columns agent](https://docs.oneschema.co/changelog/set-columns-agent).
- Osmos 2023: "the system learns from those fixes" (corrections as additional examples/formulas) — [press release](https://journalofcyberpolicy.com/?p=105190) (snippet). AI Data Wrangler "learns from your data, adapts to unique formats" — [Campus Technology](https://campustechnology.com/articles/2026/01/12/microsoft-acquires-osmos-for-agentic-ai-data-engineering.aspx) (snippet).
- Independent (Catalogit): history layer with priority over AI; schema-property embeddings cached in Redis — [Catalogit](https://dchoiboi00.github.io/projects/csv-schema-mapper-at-catalogit).

### Inferences
- "Learning" in these products is overwhelmingly **retrieval of prior decisions**, not weight updates. Flatfile's cross-tenant model is the only documented statistical learner and it is a single shared model, not per-workspace.
- Correction capture happens at the point of human confirmation in the mapping UI: the accepted pair (source header, destination field) or (source value, enum option) becomes history/alias.

### Gaps
- No documentation of per-workspace fine-tuning, few-shot injection of a customer's past mappings into an LLM prompt, or negative examples (storing rejected suggestions) from any vendor.

## Key Question 6 — Validation on the mapped output before a user sees it; published failure modes / lessons learned

### Takeaway
Every product runs schema validation (type, required, unique, regex, picklist membership) plus developer hooks (row/column/bulk hooks or validation webhooks) **after** mapping and **before** the review table is shown, with errors rendered per cell and routing controlled by an invalid-data policy; published lessons (mostly independent) converge on splitting LLM work into small steps, applying mappings deterministically, and never auto-applying silently.

### Cited Findings

**Validation / hooks**
- Dromo hook order: column hooks "at the beginning of the data review step" (once, after column matching; input `{index,value}[]`, output `{index,value?,info?}[]`); batch row hooks on init only (slices of `batchRowHookBatchSize`, default 2000); standard and bulk row hooks on init and after edits (`mode: "init" | "update"`); step hooks `UPLOAD_STEP` (first 20 raw rows preview), `REVIEW_STEP` (receives `rawHeaders`, `headerMapping`, `fields`, `fileHeaderIndex`…, runs before row/column hooks), `REVIEW_STEP_POST_HOOKS`, `REVIEW_STEP_PRE_SUBMIT`; instance methods `addField`, `removeField`, `updateInfoMessages`, `addRows`, `removeRows`; info levels `info|warning|error` (errors count as validation errors and interact with `invalidDataBehavior`) — [Dromo hooks reference](https://developer.dromo.io/reference/hooks.md). `invalidDataBehavior` default `"REMOVE_INVALID_ROWS"`, options `"BLOCK_SUBMIT"` (disables Finish) and `"INCLUDE_INVALID_ROWS"`; Bulk Fix step for select values with `maxMappableSelectValues` default 50 (max 1000) — [Dromo settings](https://developer.dromo.io/reference/settings/settings.md).
- OneSchema validation webhook: runs "every time your template is mapped to a sheet" alongside built-in validations; row hooks batched (default 1000 values/request), column hooks send ALL rows in one request; response = array of `{row_id, column, severity, message, suggestion?, options?}` (`column_index` required for custom/multi-mapped columns); 30-second timeout, retried up to three times with exponential backoff (also on 408/429, not other 4xx/5xx); `request_id` stable across retries; "The user may choose whether or not to accept the suggested value" — [OneSchema validation webhook](https://docs.oneschema.co/docs/validation-webhook). In-memory "code hooks" run validation inside OneSchema without a backend — [OneSchema code hooks](https://docs.oneschema.co/docs/code-hooks) (snippet). Templates carry "50+ built-in validations" — [FileFeeds getting started](https://docs.oneschema.co/docs/getting-started-filefeeds). "Guided error fixing": contextual suggestions, "show error" highlighting, delete-all-error-rows, "Export to Excel" error summary — [guided error fixing](https://docs.oneschema.co/changelog/guided-error-fixing).
- Ingestro validations: `required`, `unique` ("no duplicates can be entered within a column"), `regex`, cross-column `required_with`, `required_without`, `required_with_all`, `required_without_all`, value-based `required_with_values`; since v3.6.0 `required` no longer affects the mapping step — `mappingValidation` does; cleaning functions = callbacks after events; step handler functions at upload / header selection / mapping / review; `enableMassiveErrorAlert` pops up above x erroneous cells — [Ingestro columns](https://docs.ingestro.com/sdk/columns), [overview](https://docs.ingestro.com/sdk/overview), [settings](https://docs.ingestro.com/sdk/settings).
- Osmos: AutoClean runs before the server-side validation webhook, which returns final values/errors/warnings — [Configuring AutoClean](https://42layers.gitbook.io/developer-docs/configuring-autoclean-for-your-uploader) (snippet).
- CSVbox: column type + rules; errors show "how to fix it"; `Required`; `Read only` on the Verify Data step — [Column Options](https://help.csvbox.io/dashboard-settings/sheet-options).
- Impler: base/advanced/custom validation code incl. external DB/API checks; invalid data shows a tooltip for fixing before submission — [docs.impler.io/llms.txt](https://docs.impler.io/llms.txt).
- Flatfile: destination fields in the plan carry `constraints` (e.g. `required`); option-field values not in the allowed set "show an error in the review table" — [Retrieve Mapping Information](https://support.flatfile.com/en/articles/8148440-retrieve-mapping-information), [support: Mapping Data](https://support.flatfile.com/articles/8569925090-mapping-data).

**Published failure modes / lessons**
- Dromo (vendor): failure modes listed — mismatched or missing columns, invalid formats/values, "Upload Failed" on large files, and mis-mappings that do not trigger an error; one unnamed company had ">50% of its self-service CSV uploads failed" before adopting a smarter importer — [Dromo blog Sept 2025](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching).
- CSVbox (vendor): "a wrong match can corrupt data without any visible error"; recommend sample-value checks and never auto-applying low-confidence silently — [CSVbox AI column mapping](https://csvbox.io/resources/ai-column-mapping).
- Catalogit (independent, 2025–26): first PoC sent the whole CSV + full schema in one prompt — "worked often enough to be encouraging and rarely enough to be useless"; problems: confident wrong mappings ("credit" → a financial field), missed equivalences ("medium" vs "materials"), hallucinated properties, "No confidence signal or way to defer to a human", quality degrading on late columns in long prompts; diagnosis: the model was doing retrieval, classification and reasoning at once with no fallback; fix: LLM profiles each column once (types, format patterns, semantic descriptors), deterministic embedding match + type/structure filters + history; results: backlog 16 weeks → 4, >85% suggestions accepted, 15–30 s per CSV — [Catalogit](https://dchoiboi00.github.io/projects/csv-schema-mapper-at-catalogit).
- Potapov (independent, Feb 2026): "The LLM touches 100 rows. `pandas` processes 10 million."; LLM output varies between runs ("One name was parsed two different ways across calls") so no row-level LLM; shape gate flags >5% row-count deviation and blocks >10%; distribution checks (e.g. swapped first/last names); LLMs weak at non-exact dedup — use `dedupe`/`recordlinkage`; ~$2 per 10,000 LLM-routed names; CSV in prompts uses 50–56% fewer tokens than JSON — [dev.to](https://dev.to/potapov/ai-data-cleaning-in-production-from-toy-demos-to-real-pipelines-m17).
- Adjacent vendor (Akeneo Supplier Data Manager) states its mapping AI looks at "column names, sample values from the actual data rows, and target field names and descriptions", works best with descriptive headers and representative samples, and does not retain data between sessions — [Akeneo help](https://akeneo.helpjuice.com/supplier-data-manager-how-the-modules-work/supplier-data-manager-mapping-how-to-use-the-mapping-module) (snippet).

**Patents (none found assigned to the named vendors)**
- US11836120B2 "Machine learning techniques for schema mapping" — graph neural networks over source/target schemas — [Google Patents](https://patents.google.com/patent/US11836120).
- US12411814B2 "Metadata based mapping assist" — ML model trained on schema field metadata to suggest source→target mappings — [Google Patents](https://patents.google.com/patent/US12411814).
- US20220342901 "Mapping of unlabeled data onto a target schema via semantic type detection" — ML picks a field cluster per column — [ipiq record](https://ipiq.io/patents/598322).
- US10546057B2 "Spreadsheet program-based data classification for source target mapping" (older) — [Google Patents](https://patents.google.com/patent/US10546057).

### Inferences
- The industry contract is: mapping → hooks/validation → review table with per-cell errors → policy (`BLOCK_SUBMIT` / remove / include) → submit. AI never writes directly to the destination; it writes to a reviewable intermediate.
- The independent write-ups and CSVbox's explainer agree on the same design that Flatfile/Ingestro encode: small LLM tasks, deterministic application, history first, explicit confidence with a human fallback, and a silent-wrong-mapping as the top risk.

### Gaps
- No vendor publishes error-rate or mapping-accuracy benchmarks with methodology; Flatfile's ">90% of matching actions" and "95% of fields auto-mapped", Dromo's "up to 98%" are unqualified marketing figures.
- No Hacker News/Reddit threads by Flatfile, OneSchema or Dromo engineers on mapping architecture surfaced in searches.
- No patents assigned to Flatfile, OneSchema, Dromo, Osmos, or nuvo were found via general search (a USPTO assignee search was not performed).
