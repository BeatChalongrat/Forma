# ศูนย์ตรวจสอบย้อนหลัง

เปิดจากเมนู **ตรวจสอบย้อนหลัง** (`/inspection`) หรือปุ่มในหน้ารอบงาน ไฟล์ ห้องทำงาน ประวัติการตัดสินใจ และงานรายงานในแชต

## ก่อนและหลัง

ก่อน: กิจกรรม agent, เวอร์ชันการจับคู่, คำตอบ, การแก้ข้อมูล และรายงานอยู่คนละหน้า ต้องไล่ตามรหัสงานเอง

หลัง: เลือกงานหนึ่งรายการแล้วเปิดเหตุการณ์และหลักฐานในหน้าเดียว โดยยังคงหน้าตรวจสอบเดิมทั้งหมด มีทางไปทำงานต่อในหน้าต้นทาง

- ค้นหาชื่อไฟล์ รหัสงาน ลูกค้า รอบงาน สถานะปัจจุบัน และวันที่รับงาน
- ไฟล์ที่ยังไม่รู้ลูกค้าก็มีประวัติได้ ผู้ใช้ที่จำกัดสิทธิ์ลูกค้าไม่เห็นไฟล์ที่ยังไม่ระบุลูกค้า
- รวมไฟล์ต้นทาง งานประมวลผล กิจกรรมและเครื่องมือทุกครั้งที่ลอง การจับคู่ คำถาม คำตอบ การใช้ความรู้ การแก้ข้อมูล และไฟล์ส่งออก
- แยกแท็บผู้ช่วยและรายงานส่วนตัว ตรวจเจ้าของและขอบเขตสิทธิ์ของแชตทุกครั้ง รวมถึงเมื่อเปิดลิงก์ตรง
- แสดงคำตอบและผลตรวจจากฐานข้อมูลจริง ค่า `false` และ `0` ยังคงแสดง ไม่แปลงเป็นค่าว่าง
- รายละเอียดการจับคู่มีแท็บหลักฐาน บันทึกเครื่องมือที่แบ่งหน้า และข้อมูลต้นฉบับที่ผ่านการปกปิดข้อมูลลับ
- ใช้ URL เก็บตัวกรอง งาน เหตุการณ์ และหน้าประวัติ Browser Back/Forward และ refresh จึงคืนบริบทเดิมได้

## แหล่งข้อมูลและข้อจำกัด

API `/api/inspection` เป็น read model ไม่มีการสร้างบันทึกซ้ำหรือเรียกโมเดล อ่านตารางธุรกิจ AuditLog และ activity journal เดิม ใช้การเชื่อมรหัสจริง ไม่จับงานด้วยชื่อไฟล์ที่คล้ายกัน

รายการงานครั้งละ 25 รายการ เหตุการณ์ครั้งละ 50 รายการ ใช้ cursor `(timestamp, event_key)` รวม journal กับฐานข้อมูล รองรับเวลาซ้ำและกิจกรรมใหม่เข้ามาระหว่างเปิดหน้าประวัติ

ตัวกรองวันที่อิง UTC และเขียนกำกับในหน้าจอ เวลาแต่ละรายการแสดงตามการตั้งค่าผู้ใช้ เหตุการณ์เรียงใหม่ไปเก่า มีปุ่มอัปเดตเองเพื่อไม่ให้หน้ากระโดดระหว่างอ่าน

งานเก่าอาจไม่มี journal ละเอียด ส่วนข้อมูลในรายละเอียดที่แก้ไขได้จะแสดงค่าปัจจุบัน ประวัติการเปลี่ยนแปลงต้องอ่านจาก audit และเวอร์ชันที่บันทึกไว้ ไม่อ้างว่าเป็นสถานะ ณ เวลานั้นถ้าไม่มี snapshot

“สร้างไฟล์สำหรับดาวน์โหลด” หมายถึงสร้าง export แล้ว ไม่ใช่หลักฐานว่าผู้ใช้ดาวน์โหลดไฟล์สำเร็จครบทุกไบต์

ข้อมูลยาวมีเพดานการแสดงเพื่อไม่ให้หน้าค้าง สามารถแบ่งหน้า log หรือไปหน้าต้นทางได้ การไม่พบเหตุการณ์ไม่แปลว่าผ่านการตรวจ หาก journal เปิดไม่ได้จะแจ้งว่าประวัติไม่ครบ

ศูนย์นี้รวมประวัติตามงาน ไม่แทนที่ server stdout, metrics หรือ audit การตั้งค่าทั้งระบบ ซึ่งยังอยู่ในสถานะระบบและการตั้งค่า

## การตรวจสอบรอบนี้

- Backend: `tests/test_inspection_center.py` 8 กรณี ตรวจสิทธิ์ทุก drilldown, แชตส่วนตัว, incognito, redaction, read-only, วันเริ่ม/สิ้นสุด, pagination, เหตุการณ์เวลาเดียวกัน, งานใหม่ระหว่างแบ่งหน้า และ journal unavailable
- ใช้ pipeline จำลองจริงสร้าง mapping และ journal แล้วตรวจว่าเปิดอ่านจากหน้ากลางได้ โดยปิด transport ของผู้ให้บริการโมเดลใน tests
- Regression ที่เกี่ยวข้อง: `test_inspection.py`, `test_activity.py`, `test_document_reports.py` รวมกับชุดใหม่ผ่าน 31 กรณี และข้าม Docker renderer 8 กรณีซึ่งไม่ได้อยู่ในขอบเขตการแก้หน้านี้
- Frontend 33 tests ผ่าน รวม URL/การกลับ และช่องวันที่ว่าง; TypeScript/Vite build ผ่าน
- Ruff ไฟล์ใหม่และ mypy 165 source files ผ่าน ส่วน lint รวมยังมี warnings เดิมในไฟล์อื่น และ bundle warning ของ Vite
- เปิด frontend build กับ API/SQLite ชุดทดลองแยก ตรวจ light/dark, โหลดรายการ, เปิดรายละเอียด, ปุ่มกลับและ Browser Back จริง

ไม่มี API เสียเงิน ไม่มีการย้าย/ลบข้อมูล dev และยังไม่ commit หรือ rebuild Docker dev ต้องนำ backend/frontend build ใหม่ขึ้น dev จึงจะเห็นเมนูนี้ใน stack เดิม
