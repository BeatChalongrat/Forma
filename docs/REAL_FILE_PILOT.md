# เตรียม FORMA ก่อนทดลองไฟล์จริง

ตรวจค่าที่รันบน localhost วันที่ 5 พฤศจิกายน 2026 โดยอ่าน config เท่านั้น ไม่เปลี่ยนค่าและไม่เรียกโมเดล

## ค่าที่ตั้งไว้แล้ว

| เรื่อง | ค่าปัจจุบัน |
|---|---|
| AI | `openai_compatible`, `deepseek-flash`, `https://api.deepseek.com/v1`, มี API key แล้ว |
| Workflow | `graph` และเปิด mapping lab; socket `/run/sandbox/runner.sock` |
| ฐานข้อมูล/ที่เก็บไฟล์/คิว | PostgreSQL / S3-compatible MinIO / Redis + ARQ |
| งานต่อ worker | `FORMA_WORKERS=4`; ปัจจุบันมี worker container 1 ตัว |
| การอ่านไฟล์ภายในงาน | `FORMA_FILE_WORKERS=4` |
| คิว | `FORMA_QUEUE_MAX=500` |
| เรียก provider พร้อมกัน | `FORMA_LLM_SHARED_CONCURRENCY=4` |
| เพดานจำนวนคำขอ provider | `FORMA_LLM_SHARED_RPM=60` เป็นเพดานที่ FORMA ตั้ง ไม่ใช่โควตาที่ provider รับประกัน |
| Timeout | HTTP ครั้งละ 90 วินาที; AI task budget 600 วินาที; Job 1,800 วินาที |
| Recovery | lease 90 วินาที; ตรวจ recovery ทุก 15 วินาที; ส่งงานค้างใหม่ทุก 30 วินาที |
| ขนาดไฟล์ | `FORMA_MAX_UPLOAD_MB=200` ต่อไฟล์; ไม่ได้หมายความว่า JSON/ZIP ใหญ่เท่าใดก็ได้ |
| Retention | วางแผนทุก 24 ชั่วโมง; `FORMA_RETENTION_APPLY=false` ยังไม่ลบจริง |
| Auth | `dev`, อนุญาต dev ใน prod topology สำหรับ localhost; ยังไม่ใช่บัญชีผู้ใช้ที่ยืนยันตัวตนจริง |
| URL ดาวน์โหลด | `http://localhost:9000` เหมาะกับเบราว์เซอร์ในเครื่องนี้ |

ไม่ควรนำ `.env.production.example` ทับ `.env.production` ทั้งไฟล์ เพราะ example เป็นค่า default
และเว้น secret ไว้ ส่วน AI ที่บันทึกผ่านหน้า Settings อาจมีค่าทับ environment อยู่ ให้ดู effective config ในหน้าเว็บ

## สิ่งที่ต้องเลือกก่อนรับไฟล์จริง

1. **ลูกค้าและ JSON ปลายทาง** — เลือก/ลงทะเบียน JSON Schema ที่ทีมปลายทางต้องการจริง
   แล้วกำหนด default ของลูกค้าหรือเลือกรูปแบบตอนสร้างรอบ ไม่จำกัดว่าต้องเป็น product เดิม
   ระบุ field บังคับ, identity key, ชนิดข้อมูล, collection และความหมายที่สำคัญ เช่น สกุลเงิน หน่วย ราคา/VAT
   ความหมายที่ยังไม่มีหลักฐานควรให้ระบบถาม ไม่สร้าง default ทางธุรกิจจากการเดา
2. **แยกข้อมูลจำลอง** — แยกพื้นที่ทดลองไฟล์จริงหรือฐานข้อมูลจากชุดสาธิตเมื่อทำได้
   หากใช้ฐานเดิม ให้ตรวจลูกค้า mapping ที่อนุมัติ และความรู้ที่แชร์ก่อน เพื่อไม่ให้ความรู้จาก fixture มีผลกับงานจริง
   ไม่ต้องลบข้อมูลทดสอบหรือประวัติเดิมเพื่อเริ่ม pilot
3. **ให้คนตรวจรอบแรก** — ตอนอัปโหลด ปิด “อนุมัติและสร้างไฟล์อัตโนมัติ” ในรอบ pilot
   คงกฎ block เมื่อไม่มี identity, ไม่มีแถว หรือไฟล์ไม่เกี่ยวข้องไว้
   ปัจจุบัน threshold mapping=0.95, critical field=0.90, high field=0.80 และต้องเคยอนุมัติก่อนจึง auto ได้
   คะแนนความมั่นใจเหล่านี้ไม่ใช่อัตราความถูกต้องที่รับประกัน
4. **ความจำจากคำตอบ** — บันทึกความรู้เฉพาะคำตอบที่เจ้าของข้อมูลยืนยันแล้ว
   ตรวจ scope ให้ตรงลูกค้า/รูปแบบ/เงื่อนไข โดยเฉพาะ VAT หน่วย และสกุลเงิน; ไม่อนุมานให้ใช้ข้ามลูกค้าโดยอัตโนมัติ
5. **ควบคุมปริมาณและค่าใช้จ่าย** — เริ่มไฟล์ตัวแทนกลุ่มเล็กก่อน คงค่าคิว/worker ปัจจุบันได้
   ถ้า provider ตอบ 429 จึงปรับ concurrency/RPM ลงตามโควตาบัญชีจริง
   `LLM_TASK_BUDGET_S` เป็นเวลา และ `MAPPING_WORKFLOW_CALLS` เป็นจำนวน attempts ไม่ใช่ hard dollar budget
   ตรวจเครดิต/การแจ้งเตือนใช้เงินของบัญชี provider และติดตาม usage ใน FORMA; อย่าสมมติว่ามีตัวตัดค่าใช้จ่ายเป็น USD แล้ว
6. **Backup และพื้นที่ว่าง** — มี backup ทั้ง PostgreSQL, object storage และ secret สำหรับถอด API key
   เก็บสำเนานอกเครื่องและตรวจขั้นตอน restore กับ schema ปัจจุบัน โดยไม่เปลี่ยน `FORMA_SECRET_KEY` ที่ใช้อยู่โดยไม่มีแผนย้าย
   เลือกระยะเก็บ source/dataset/export ให้เหมาะกับงานก่อนเปิด retention ลบจริง

## ก่อนให้ทีมเข้าผ่านเครือข่าย

- ตั้ง `FORMA_AUTH=oidc`, issuer, audience, client ID และ role/customer claims ให้ตรงระบบบัญชีองค์กร
  จากนั้นปิด `FORMA_AUTH_ALLOW_DEV_IN_PROD`; แบ่งสิทธิ์ importer/reviewer/approver/admin ตามผู้ใช้งาน
- ใช้ HTTPS และกำหนด public URL/CORS ให้ตรงโดเมนที่เปิดจริง
- เปลี่ยน public endpoint ของ S3/MinIO ให้เครื่องผู้ใช้เข้าถึงได้ ไม่ใช่ localhost ของแต่ละคน
  ทดสอบดาวน์โหลด source และ ZIP จากเครื่องผู้ใช้จริง
- จำกัดการเข้าถึง database/Redis/storage และกำหนดผู้รับผิดชอบเมื่อมี failed job หรือคิวค้าง

## ขั้นตอนเริ่ม pilot

1. `/ready` ต้อง `ok`; ตรวจว่ามี worker ทำงาน และทราบที่มาของ failed เก่า 5 งานก่อน ไม่กด retry ทั้งหมด
2. เลือกไฟล์จริงที่ได้รับอนุญาตให้ส่งตัวอย่างข้อมูลไปยัง provider; ปกปิดข้อมูลที่ไม่จำเป็น
3. สร้างรอบแยก ตั้งชื่อ/วันที่/จำนวนไฟล์ที่คาดว่าจะได้รับ และปิด auto publish สำหรับรอบแรก
4. ตรวจคำถามและหลักฐาน แล้วเทียบ JSON กับต้นฉบับทั้ง identity, จำนวนแถว, ราคา, หน่วย, วันที่ และความสัมพันธ์ข้ามชีต
5. ทดลองไฟล์แก้ไข/อัปโหลดซ้ำ ตรวจเวอร์ชันและ manifest ก่อนส่ง JSON ให้ระบบปลายทาง
6. เมื่อผ่านจึงเพิ่มจำนวนและเลือกเปิด auto เฉพาะกรณีที่กฎอนุญาต
