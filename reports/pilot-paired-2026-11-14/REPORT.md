# ผล pilot: ชุดคู่เทียบและการตรวจหลักฐาน

วันที่ 14 พฤศจิกายน 2026 — ยังไม่ commit ไม่เรียก API เสียเงิน ไม่เปลี่ยนฐาน/volume/config ของ dev

## ก่อนและหลัง

## ผลทดสอบฟรี

- Regression ที่เกี่ยวข้อง **65 passed** ครอบคลุม scorer/agent harness/pilot/การตรวจสิทธิ์และเก็บคำตอบ
- Ruff lint/format ผ่าน; mypy ผ่าน source ที่เปลี่ยนทั้ง 2 ไฟล์; JavaScript syntax และ Git whitespace ผ่าน
- ชุดคู่เทียบ 8 กรณี รันทั้ง rules และ mock echo มี 18 mock calls ไม่มีคำขอถึงผู้ให้บริการจริง
- Excel staging 3 ชีต 12 สินค้า ผ่านอัปโหลด → mapping → ตอบคำถาม → preview → ยืนยัน → คนอนุมัติ → ดาวน์โหลด
- Refresh และ Browser Back รักษาคำตอบ; ยืนยันซ้ำได้ job เดิม
- การบันทึกร่างชนกันได้ 200/409; แก้ข้อมูลชนกันได้ 201/409
- ก่อนอนุมัติส่งออกถูกปฏิเสธ หลังอนุมัติดาวน์โหลดได้
- ตรวจรหัส ชื่อ ราคา หน่วยต่อแพ็ก คลังสินค้า 2 แห่งต่อสินค้า และโปรโมชั่น/วันที่ครบทั้ง 12 รายการ
- Restart แล้วดาวน์โหลดเหมือนเดิม; backup/restore ในฐานและ bucket ใหม่ภายใน staging ได้ checksum เดิมและ 12 รายการครบ
- รอบ browser สุดท้ายใช้ประมาณ 14.37 วินาที เป็นเวลา automation ไม่ใช่เวลาคนตรวจ
- Ledger ที่รวบรวมเฉพาะงานรอบสุดท้ายมี 4 question occurrences นับต่อ mapping version ไม่ใช่อัตราถามถูก
- ค่า API **$0**; ผลความแม่นยำโมเดลจริงและ ERP จริง **ยังไม่มีการวัด**

## สิ่งที่รอไฟล์จริงและผู้ตรวจ

1. ไฟล์ ERP ที่ได้รับอนุญาตและปกปิดแล้ว พร้อม schema/ความหมายข้อมูลปลายทาง
2. ผู้ตรวจอิสระยืนยัน gold จากต้นทางก่อนดูผลระบบ; เฉลยจำลองตอนนี้ยังไม่ใช่ gold ของเจ้าของข้อมูล
3. วัดโมเดลจริงผ่าน graph เต็มด้วยข้อมูลเดียวกับกฎ ทั้งก่อนและหลัง human-in-loop
4. ให้คนใช้งานจริงจัดประเภทคำถามและจับเวลา เทียบ manual/rules-assisted/AI-assisted โดยลดผลจากการจำเฉลย
5. ผู้ตรวจอีกคนสุ่มตรวจหลังอนุมัติและลองรับ JSON ในระบบปลายทาง

คำสั่งรันและขั้นตอนดู `docs/PILOT_PAIRED_EVALUATION.md`
ชุดนี้พร้อมใช้ซ้อมและเก็บหลักฐาน แต่ยังไม่ใช่ผลยืนยัน production กับ ERP จริง

## ผลหลังเพิ่มการตรวจหลักฐาน 6 ข้อ

ตรวจของเดิมพบว่าเครื่องมือสำรวจไฟล์, ลอง candidate mapping, full execution และ Semantic Reviewer มีอยู่แล้ว
จึงเติมช่องว่างในเส้นทางเดิม ไม่เพิ่ม agent อีกชุดหรือ alias สำหรับชื่อในไฟล์ทดสอบ

| จุด | ก่อน | หลัง |
|---|---|---|
| ฟิลด์ที่ยัง map ไม่ได้เลย | Grounding เริ่มจากฟิลด์ที่มี mapping แล้ว จึงอาจไม่ได้ตรวจช่องที่หายไป | ส่ง candidate จากชนิดค่า คำอธิบาย schema และตัวอย่างให้ mapper/Evidence Analyst พร้อมให้ grounding เริ่มตรวจฟิลด์ที่ขาด |
| ชื่อคอลัมน์ไม่คุ้น | กฎชื่ออาจตัดตัวเลือกก่อนถึงขั้นสำรวจ | คงตัวเลือกที่ชนิดค่าเข้ากันแม้ชื่อไม่คล้าย ไม่เลือกจากตัวเลขหรือคอลัมน์ที่เหลือโดยอัตโนมัติ; แสดงว่ารายการถูกตัดทอนหรือไม่ |
| สกุลเงินและขอบเขต | P06 ไม่ส่งคำถามขัดแย้งออกมา; semantic currency ไม่มี default อาจได้ THB | ตรวจ schema/source values, แยกคนละ currency target, รองรับ source contract ที่เจ้าของข้อมูลระบุ; ไม่มีหลักฐาน/default ไม่เติม THB |
| การตรวจอิสระ | ตัวเลขและ schema ผ่านไม่ได้รับประกันว่าขอบเขตถูก | Full verifier ส่ง decision questions และ service ตรวจซ้ำก่อนอนุมัติ; confidence 1.0 หรือ override ไม่ข้ามคำถามที่ยังไม่ตอบ |
| การถามและความจำ | คำถาม confidence กับข้อสงสัยโมเดลอาจซ้ำหัวข้อ; ยังไม่มี receipt สำหรับ scope นี้ | หนึ่งคำถามพร้อมคอลัมน์/ค่าอ้างอิง เลือก source โดยคงค่ารายแถว; บันทึกผู้ตอบกับหลักฐาน และยืนยันใหม่หาก schema/ไฟล์/การอ่าน/การเชื่อมข้อมูล/คำตอบเปลี่ยน |
| การพิสูจน์ | มี corpus คงที่ แต่ไม่ทดสอบกลไกใหม่นี้ | เพิ่ม metamorphic tests เปลี่ยนภาษา/ชื่อ/ตำแหน่ง, ข้อมูลลวง, source aliases, เปลี่ยน join, หลักฐานขาด/ขัดกัน/มี authority และทดสอบบน mock staging |

### ก่อน–หลังของ corpus เดิม ต้องอ่านอย่างไร

- P06 จากไม่พบคำถามใน component เป็นคำถามเลือกแหล่งสกุลเงิน 1 ข้อ ทั้งฝั่ง rules และ mock echo
- P04 ที่มี 22/09 เป็นหลักฐานลำดับวัน/เดือนยังได้ผลถูก และ P05 ที่กำกวมยังต้องถาม
- คะแนน answerable fields ของ rules/echo ใน 8 กรณียังเฉลี่ย **87.5%** เท่าเดิม ไม่ได้ปรับ alias เพื่อดันคะแนน
- P03 ยัง 0/3 ใน **echo mock** เพราะ mock ส่ง draft กฎเดิมกลับมา ไม่ได้ตีความภาษาใหม่; ผลนี้ไม่ใช่คะแนน DeepSeek หลังแก้
- เทส mock แยกพิสูจน์ว่า mapper ได้เห็นตัวเลือกของฟิลด์ที่หายไป ขอ inspect และส่ง mapping ใหม่ผ่านการ execute ได้
  แต่ตัวเลือกของ mock ถูกกำหนดในเทส จึงเป็นหลักฐานการต่อระบบ ไม่ใช่ความฉลาดของโมเดล

### ขอบเขตที่ยังต้องวัดกับของจริง

1. ยังไม่มีไฟล์ ERP จริงหรือรอบ live model ในงานนี้ จึงยังบอกอัตรา map ถูก/ถามถูกของ DeepSeek หลังแก้ไม่ได้
2. Currency evidence ใช้ profile samples/unique counts และ scope ที่ตรวจพบ ไม่ใช่การรับรองว่าเทียบทุกเซลล์หรือเข้าใจชื่อทุกภาษา
3. ชื่อใหม่ไร้คำอธิบายหรือมีหลายความหมายยังต้องสำรวจเพิ่มหรือถาม ไม่เติมค่าให้ครบเพื่อผ่าน schema
4. คำตอบที่ยืนยันใช้กับสายเวอร์ชันและหลักฐานของงานนั้น; การนำความรู้ข้ามรอบยังต้องผ่าน compatibility เดิม ไม่คัดลอก receipt ข้ามงาน
5. การมีคนยืนยันก่อนส่งออกยังคงอยู่ และควรวัดกับไฟล์จริง/ผู้ตรวจอิสระก่อนขยายการใช้งาน
