# ชุดไฟล์ ERP หกแบบ สามรอบส่ง — สำหรับทดสอบกับ AI จริง

ไฟล์ทุกไฟล์สร้างจากแคตตาล็อกเดียวกัน (`manual_test_files/tools/catalogue.py`: สินค้า 12 รายการ โปรโมชั่น 4 รายการ
คลัง 2 แห่ง) แต่เขียนออกมาตามนิสัยของระบบต้นทางแต่ละระบบ แต่ละลูกค้ามี 3 โฟลเดอร์:

| โฟลเดอร์ | ความหมาย | สิ่งที่ควรเกิด |
|---|---|---|
| `r1` | ส่งครั้งแรก (ลูกค้าใหม่) | AI อ่านไฟล์ เสนอ mapping ถามเฉพาะเรื่องที่ไฟล์ไม่บอก คนตรวจแล้วอนุมัติ |
| `r2` | ส่งครั้งที่สอง โครงสร้างเดิม ราคา 2 รายการและสต็อก 3 รายการเปลี่ยน | ใช้ mapping เดิมจากความจำ ผ่านเองโดยไม่ถาม |
| `r3` | ส่งครั้งที่สาม โครงสร้างเปลี่ยน (เปลี่ยนชื่อคอลัมน์ / เพิ่มคอลัมน์ / ย้ายชีต / ความหมายเปลี่ยน) | ระบบเห็นว่าเปลี่ยน ปรับ mapping โดยไม่เสียฟิลด์เดิม หรือหยุดถามเมื่อข้อมูลเปลี่ยนความหมาย |

ทุกโฟลเดอร์มี `expected.json` (เขียนจากแคตตาล็อก ไม่ใช่จากผลของระบบ) และ `ผลที่ควรได้.md` อธิบายกับดักของไฟล์นั้น

| ลูกค้า | ระบบต้นทาง | กับดักหลัก |
|---|---|---|
| `SAPTH` | SAP (ชีต MARA / A304 / MARD + Info + legend T141T) | ราคาสุทธิไม่รวม VAT บอกไว้ในชีต Info, สถานะเป็นรหัสที่ต้องอ่าน legend, หน่วยเป็นรหัส SAP, วันที่ 01.10.2026 |
| `ACCTH` | โปรแกรมบัญชีไทย | หัวรายงาน 3 แถว ท้ายรายงาน หัวคอลัมน์ย่อ ราคาบางช่องเป็นข้อความ "1,284.00" วันที่ "1 ต.ค. 69" |
| `ODOO` | Odoo (CSV 3 ไฟล์) | ราคาก่อนภาษี + คอลัมน์ Customer Taxes, โปรเป็น pricelist item, Active=False, เชื่อม 3 ไฟล์ด้วย Internal Reference |
| `POS` | ระบบ POS ชีตเดียว | ตัวย่อล้วน (Itm No, UP, Sts A/I/D), สต็อกเป็นคอลัมน์กว้าง, โปรบนแถวสินค้า, วันที่อเมริกัน; r3 ราคาเปลี่ยนเป็นก่อน VAT โดยหัวเท่าเดิม |
| `DYN` | Business Central | ชีตราคาที่สอง (WHOLESALE), ชีตซ่อน `_calc`, Blocked / Lifecycle Stage; r3 ราคาย้ายชีต |
| `HAND` | Excel ทำมือของเจ้าของร้าน | หัวตาราง 2 ชั้น แถวหมวด แถวรวม ราคา "7.-" "฿14" "39 บาท" โปรเป็นข้อความ หมายเหตุมีข้อความสั่ง AI |

สร้างใหม่: `backend/.venv/Scripts/python manual_test_files/erp/tools/build.py`
