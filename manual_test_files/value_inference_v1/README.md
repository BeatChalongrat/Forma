# การอนุมานจากค่าจริง — เตรียมไว้ ยังไม่รัน

ชุดนี้เพิ่มจาก relationships_v1 โดยเน้นชื่อคอลัมน์กำกวม หลักฐานระหว่างตาราง และการไม่เดาความหมายจากตัวเลขอย่างเดียว ไม่ใช่ไฟล์ลูกค้าจริง

## สถานะ

- เขียนตัวสร้าง fixture และ runner แล้ว **ยังไม่สร้างไฟล์ ยังไม่เรียก API/LLM และยังไม่มีคะแนน** ตามคำสั่งวันที่ 4 พฤศจิกายน 2026
- ใช้ CSV เพื่อแยกความสามารถด้านค่าข้อมูล/ความหมายออกจากปัญหาการอ่าน workbook; ต้องรัน relationships_v1 ที่เป็น Excel ควบคู่ในรอบถัดไป
- สุ่มค่ากับลำดับได้ด้วย seed แต่ผู้พัฒนารู้ตระกูลโจทย์ จึงเป็น held-out values/layouts ไม่ใช่ blind held-out problem families
- ต้องมีชุด ERP จริงหรือชุดจากผู้ประเมินอิสระเพิ่มเติม ก่อนอ้างความสามารถทั่วไป

## 12 กรณีที่เตรียม

| กรณี | สิ่งที่ต้องพิสูจน์ |
|---|---|
| V01 | หัวคอลัมน์ A/B/C/D มีไฟล์คำอธิบายแยก: ต้องอ่านหลักฐาน |
| V02 | สลับแถว/คอลัมน์และเพิ่มไฟล์ไม่เกี่ยวข้อง: ผลต้องเท่ากับ V01 |
| V03 | รหัสซ้ำข้ามบริษัท: ต้องใช้คีย์บริษัท + รหัส |
| V04 | จำนวนกล่อง: อ่านอัตราแปลงรายสินค้าก่อนคำนวณ |
| V05 | ไม่มีตัวคูณกล่อง: ขอข้อมูลเพิ่ม ไม่สมมติ 12 |
| V06 | ราคาปลีก/ส่ง ไม่มีข้อกำหนดเลือก: ถามเจ้าของงาน |
| V07 | ราคาเป็นจำนวนเต็ม จำนวนเป็นทศนิยม: ไม่ใช้รูปร่างตัวเลขตัดสินความหมาย |
| V08 | วันที่กำกวม ไม่มี locale: ถามรูปแบบวัน/เดือน |
| V09 | หน่วยเปลี่ยนที่แถว 451: ห้ามอ่านแค่ต้นตารางแล้วเหมารวม |
| V10 | ไม่มีราคา: ไม่จับ stock ไปเป็นราคาเพื่อให้ครบ JSON |
| V11 | Invoice contract: ไม่ hardcode ว่าทุกงานเป็น product |
| V12 | รหัสสินค้ากับ barcode เป็นตัวเลขทั้งคู่: รักษาศูนย์และแยกความหมาย |

## ขั้นตอนรอบถัดไป (ยังไม่ดำเนินการ)

1. รัน `backend/.venv/Scripts/python manual_test_files/value_inference_v1/prepare.py --seed <seed>` ครั้งเดียว เก็บ manifest/hash ห้ามสร้างใหม่ระหว่าง before/after
2. ใช้ snapshot โค้ด/ภาพ container ก่อนแก้ที่ยืนยันได้จริง ไม่ใช้ git HEAD แทน dirty working tree ก่อนหน้า บันทึก image IDs ของ API/worker; หากไม่มี baseline ที่ยืนยันได้ ให้รายงานว่าไม่มี ไม่สร้างคะแนนก่อนแก้ขึ้นเอง
3. รัน baseline ด้วย `.../python manual_test_files/value_inference_v1/run.py --run-id value-before` และ DeepSeek รุ่นเดิม
4. หลังรวมงาน framework/agents และผ่าน regression แล้ว deploy รุ่นหลัง และรัน `--run-id value-after` กับไฟล์ชุดเดียวกัน
5. รันซ้ำอย่างน้อยอีกหนึ่งรอบเพื่อดูความแปรปรวน และแยก provider failure ออกจาก mapping error
6. ตรวจคำถาม V05/V06/V08 ด้วยคนก่อนตอบผ่าน preview/apply; บันทึกผลหลังตอบแยกจาก cold run ห้ามอนุมัติ/ส่งออกอัตโนมัติ

Runner ใช้ลูกค้าใหม่ในแต่ละ run, บันทึกคำทำนายก่อนอ่าน oracle และไม่ approve/export. Oracle อยู่คนละโฟลเดอร์ ไม่อยู่ในรายการไฟล์อัปโหลด

## ตัวชี้วัด

- ความแม่นของค่าที่มีหลักฐานเพียงพอ / ค่าทั้งหมด / extra rows / extra values
- ความผิดที่ถูก auto-approve (ต้องแยกจากข้อที่หยุดถามอย่างเหมาะสม)
- ความครบและความตรงประเด็นของคำถาม: การถามถูก target อย่างเดียวไม่พอ ต้องตรวจคำถาม/action จริง
- จำนวนคำถามเกินจำเป็น และค่าที่เดาทั้งที่ขาดหลักฐาน
- V01→V02 invariance โดยเทียบตาม identity ไม่ใช่ลำดับแถว
- หลังคนตอบ: ผลถูกและไม่เปลี่ยนฟิลด์/สินค้าอื่น จากนั้นรอบเรียนรู้ต้องใช้ลูกค้าเดิมและความรู้ที่ยืนยันแล้วอย่างถูกขอบเขต
- เวลา, provider errors, จำนวน inspect/candidates/python/fix turns และ cost_usd

ไม่แสดงคะแนนหลังคนตอบเป็นความสามารถที่ AI ทำได้เอง และไม่ถือว่า null ที่ถูกต้องในกรณีขาดข้อมูลคือข้อมูลพร้อมใช้งาน
