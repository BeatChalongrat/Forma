# สรุปก่อน–หลังปรับการอนุมานจากค่าข้อมูล

วันที่ 4 พฤศจิกายน 2026 — แก้โค้ดและเตรียมการทดสอบแล้ว แต่ **ยังไม่รันเทส ไม่เรียกโมเดล ไม่ deploy และไม่ commit** ตามคำสั่งล่าสุด

## ผลตรวจของเดิมและสิ่งที่เติม

| ข้อ | ของเดิม | สิ่งที่เพิ่มในรอบนี้ |
|---|---|---|
| 1. ข้อมูลที่ AI เห็น | มี profile, raw cells, metadata, sandbox, schema และคำตอบที่จำไว้แล้ว แต่ digest ไม่บอก file ID/ขอบเขตข้อมูลครบ | เพิ่มตัวระบุไฟล์ จำนวนแถวจริง/ที่ profile และข้อความบอกการตัดคอลัมน์ พร้อมบันทึกคำตอบจากเครื่องมือลงประวัติ self-check |
| 2. อนุมานจากค่าคอลัมน์ | วิเคราะห์ type/range จาก 400 ค่าต้นคอลัมน์ และให้ hint price_like กับทศนิยมบวก | ใช้ค่ากระจายถึงท้ายคอลัมน์ เพิ่มสัดส่วนตัวเลข/จำนวนเต็ม ค่าติดลบ/ศูนย์ ศูนย์นำหน้า ตัวคั่นกำกวม และเลิกบอกว่าทศนิยมคือราคา |
| 3. พิจารณาหลายคอลัมน์/ตาราง | มี UI ตรวจความสัมพันธ์ แต่ AI ไม่มีคำสั่งทดลอง composite join โดยตรง | เพิ่ม relationships และ join inspection: คีย์ร่วมหลายคอลัมน์ ค่าที่มีอัตราส่วนสัมพันธ์กัน แถวจับคู่ไม่พบ จำนวนแถวหลัง join และ cardinality; ทุกอย่างเป็นหลักฐาน ไม่ใช่คำตัดสินธุรกิจ |
| 4. ทดลองและตรวจความหมาย | มีการรัน DSL, full verification, ตรวจยอดตาม contract และวนแก้ทีละคำตอบ | เพิ่มการเทียบ mapping 2–3 ทางเลือกใน 1 turn แยกผู้เสนอออกจากตัวรัน; เพิ่มตรวจรหัสที่เสียศูนย์นำหน้าจากค่าต้นทางจริงก่อน dedupe และแสดงในผลตรวจ |
| 5. ถาม/จำอย่างมีขอบเขต | มี typed questions, preview/apply, ตรวจผลกระทบ และ memory ตามลูกค้า/contract/layout อยู่แล้ว | เพิ่มค่าต้นทางจริงในหลักฐานบนการ์ดคำถาม เก็บขอบเขตการจำพร้อมผลตรวจย่อ และกัน memory ที่มี verification ล้มเหลว/ไม่ครบ; คงการงดใช้เมื่อคำตอบขัดกัน |
| 6. วัด format ใหม่ | มีชุด Excel ความสัมพันธ์ 12 กรณีที่เคยใช้แก้ระบบ | เตรียม generator และ runner สำหรับอีก 12 กรณี เน้นค่าข้อมูลและความหมาย แยก oracle และ source พร้อมเกณฑ์คำถาม/การอนุมัติผิด/ต้นทุน แต่ยังไม่สร้าง fixture หรือรัน |

## สิ่งที่ตรวจแล้วในรอบนี้

- Ruff ตรวจไฟล์ backend/tests ที่แก้: ผ่าน
- Mypy ตรวจ source 138 ไฟล์: ผ่าน
- อ่าน syntax ของสคริปต์เตรียม/รัน evaluation 2 ไฟล์โดยไม่ import หรือ execute: ผ่าน
- ยังไม่รัน pytest, integration tests, model evaluation หรือชุดจำลองใด ๆ
- ตัวเลข 97.83% / 100% จาก relationships_v1 รอบก่อนเป็นผลของโค้ดรุ่นก่อนหน้า ไม่ใช่คะแนนของงานรอบนี้

## สิ่งที่คาดว่าจะได้ แต่ยังต้องวัด

- หัวคอลัมน์ชื่อแปลกจะมีหลักฐานจากค่าจริงและตารางอื่นให้ AI ใช้มากขึ้น
- ตัวเลือก join ที่ทำให้แถวเพิ่ม/หายมีเครื่องมือช่วยตรวจ ก่อนส่ง mapping สุดท้าย
- AI ไม่ถูกชี้นำว่าตัวเลขทศนิยมต้องเป็นราคา หรือเลขที่เหลือต้องเป็น stock
- คำถามมีตัวอย่างจากไฟล์จริง คนจึงเห็นว่ากำลังตัดสินเรื่องใด
- ยังไม่มีหลักฐานว่าคะแนนเพิ่มขึ้นหรือคำถามลดลง ต้องวัดด้วยโมเดลเดิมหลังรวมงาน framework

## ข้อจำกัดและงานต่อสำหรับ framework/agents

1. Observation เป็นตัวอย่างที่มีขอบเขต: profile สูงสุด 50,000 แถว, รูปแบบค่าจาก 400 จุด, ความสัมพันธ์จาก 2,000 จุดและไม่เกิน 12 คอลัมน์ต่อคำขอ; AI ขอเลือกคอลัมน์อื่นเพิ่มได้ และ final mapping ยังตรวจครบทั้งไฟล์
2. ค่า/อัตราส่วนที่สัมพันธ์กันไม่พิสูจน์หน่วย สกุลเงิน ประเภทราคา หรือความหมาย ต้องอาศัย source/contract/คนตอบ
3. Profile เก่าจะไม่มี observations ใหม่จนกว่าจะ profile อีกครั้ง
4. การตรวจศูนย์นำหน้าครอบคลุม root identity ที่อ่านจากคอลัมน์เดียว ยังไม่ใช่ตัวตรวจความหมายสากลทุกสูตร/collection
5. Legacy approvals ที่ไม่มี verification snapshot ยังใช้ compatibility เดิม; ไม่ถือว่าได้รับการตรวจใหม่ในรอบนี้
6. ชุดใหม่เป็น CSV เพื่อแยกการอนุมานความหมายออกจาก Excel parsing ต้องใช้คู่กับ relationships_v1 และเพิ่มไฟล์ ERP จริง/โจทย์จากผู้ประเมินอิสระ
7. แยกโมดูลตามหน้าที่แล้ว แต่ยังไม่ได้เพิ่ม framework หรือเปิดหลาย agent: Evidence discovery → Mapping proposal → Candidate execution → Semantic verification → Human decisions → Scoped memory ใช้เส้นทางอนุมัติเดิมร่วมกัน
