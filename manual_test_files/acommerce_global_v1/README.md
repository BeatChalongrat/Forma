# ชุดทดสอบ aCommerce หลายประเทศ รุ่น 1

วันที่เตรียม: 2 พฤศจิกายน 2026

ชุดนี้เป็นข้อมูลจำลองเพื่อหาข้อผิดพลาด ไม่ใช่ไฟล์ลูกค้าจริง และยังไม่ได้รันโมเดลเพื่อวัด mapping รอบใหม่

## สิ่งที่อยู่ในชุด

- 16 กรณี / 20 รอบ / 22 ไฟล์ต้นทาง: Excel 6 ไฟล์ และ CSV/TSV 16 ไฟล์
- 12 SKU ต่อรอบหลังแก้ความกำกวมครบ บางต้นทางมี 24 แถวเพราะหลายคลังหรือประวัติราคา และหนึ่งกรณีมี 13 แถวเพราะข้อมูลขัดแย้ง
- 12 กรณีที่หลักฐานเพียงพอ และ 4 กรณีที่ต้องถามผู้ใช้ก่อนตัดสิน
- รอบซ้ำและรอบเปลี่ยนความหมาย: G02 และ G03 มี r1/r2/r3
- JSON ปลายทาง 2 แบบ: product เดิม และ commercial-offer สำหรับทดสอบ G05 ซ้ำโดยเปลี่ยนสัญญาปลายทาง
- เฉลย 240 product records และ 12 commercial offers แยกจากไฟล์ที่ให้ผู้เข้าแข่งขัน

## โครงสร้าง

- `inputs/<case>/<round>/`: Excel/CSV/TSV และ `task.md` ที่ต้องส่งให้ทุกระบบเท่ากัน
- `schemas/`: JSON Schema ปลายทาง
- `oracle/<case>/<round>/`: expected.json, review.json และผลที่ควรได้ **ห้ามส่งให้โมเดล**
- `manifest.json`: รายการไฟล์ SHA-256 รอบ ประเภทโจทย์ และเส้นทางเฉลย
- `RESEARCH.md`: หลักฐานลูกค้า ตลาด และขอบเขตที่คาดการณ์ได้
- `BENCHMARK-PROTOCOL.md`: วิธีเทียบ FORMA กับการส่งไฟล์ตรงให้ ChatGPT/Claude
- `VALIDATION.json`: ผลตรวจไฟล์และเฉลย ไม่ใช่ผล accuracy ของ AI

## ตารางกรณี

| กรณี | สิ่งที่ทดสอบ | ผลที่ต้องการ |
|---|---|---|
| G01 | ไทย, SAP-like master/price/stock สาม Excel, แถวสลับลำดับ | join ตาม SKU, ศูนย์นำหน้าครบ, stock เป็นชิ้นไม่คูณแพ็กซ้ำ |
| G02 | Indonesia, `1.234,56`, semicolon CSV, Bahasa | อ่านทศนิยมถูก และ r3 เปลี่ยน locale ต้องตรวจใหม่ |
| G03 | Malaysia, 2 คลังต่อสินค้า | 24 แถวเป็น 12 SKU; r3 stock เปลี่ยนจากชิ้นเป็นลัง 12 ชิ้น |
| G04 | Philippines, footwear size/color | รักษา variant ไม่รวมตาม parent style หรือชื่อสินค้า |
| G05 | Singapore, SGD/USD คนละแถว | รักษาสกุลเงินและวันที่; ทำ target สองแบบจาก input เดียวกัน |
| G06 | French beauty spreadsheet | ช่องว่าง/narrow NBSP + comma + € ต้องเป็นจำนวนที่ถูก |
| G07 | German numeric convention | `1.234` เป็น 1234 จากหลักฐาน de-DE; วัน.เดือน.ปี |
| G08 | US-format date จากสำนักงานใหญ่ | `03/04` เป็น March 4 เพราะหัวคอลัมน์ระบุ MM/DD |
| G09 | ญี่ปุ่น UTF-16LE BOM TSV | encoding/หัวภาษาญี่ปุ่น/ชื่อสินค้า/รหัสไม่เสีย |
| G10 | เกาหลี Excel | หัวภาษาเกาหลีและ barcode/SKU ที่มีศูนย์นำหน้า |
| G11 | ราคาเก่าและใหม่ | เก็บเฉพาะ active ตาม task; ห้ามคืน standard สองราคา |
| G12 | ภาษีรายแถว | รักษา included และ rate แต่ละแถว ไม่เหมารวมทั้งไฟล์ |
| G13 | วันที่ `03/04` ไม่มี locale | ถามวันที่ก่อนเผยแพร่ |
| G14 | ราคา `$` ไม่มีรหัส currency | ถามสกุลเงิน ไม่เดาจาก schema default |
| G15 | `BT` ไม่มีคำอธิบาย | ถามความหมายหน่วย ไม่ใช้ global alias อัตโนมัติ |
| G16 | SKU เดียวสองราคา ไม่มีเวลา | ถามว่าจะใช้รายการใด ไม่ last-row-wins |

G06–G10 เป็นการจำลองต้นทางจากสำนักงานใหญ่/ซัพพลายเออร์ ไม่ใช่ข้ออ้างว่า aCommerce มีตลาดขายในประเทศเหล่านั้น ชื่อสินค้าทั้งหมดเป็นชื่อสมมติ ภาษี 5%/0% เป็นค่าของ fixture ไม่ใช่อัตราภาษีตามกฎหมายของประเทศ

## วิธีใช้ที่สำคัญ

1. อ่าน BENCHMARK-PROTOCOL.md ก่อน การผ่าน reader ไม่เท่ากับ mapping ถูก
2. ส่งเฉพาะไฟล์ใน manifest พร้อม task.md และ schema ที่เลือกให้แต่ละระบบ
3. กรณี G13–G16 expected.json คือเฉลย **หลังได้รับคำตอบจากผู้ใช้**; ก่อนหน้านั้นประเมินความสามารถในการถาม ไม่บังคับให้เดาให้ตรงเฉลย
4. ไม่ใช้ airun.py เดิมโดยตรงกับชุดนี้ เพราะโครงสร้างแยก oracle และตัวจำลองผู้ใช้เดิมเลือก confirm/choice อัตโนมัติ พร้อมขั้น approve/export ซึ่งจะทำให้การวัดการถามกลับผิดจุด
5. การรัน stack รอบถัดไปต้องมีตัวควบคุมการทดลองที่บันทึกก่อนตอบและหลังตอบ พร้อมส่ง task.md เป็นบริบทจริง หากเส้นทาง FORMA ยังส่งบริบทนี้ไม่ได้ให้บันทึกเป็นช่องว่างของระบบ ห้ามให้ข้อมูลเฉพาะคู่แข่งแล้วเรียกการทดลองนั้นว่าเท่าเทียม

## ขอบเขต

เป็นชุดตรวจเชิงหน้าที่ขนาดเล็ก ยังไม่ใช่ load test 300 ไฟล์ ไม่มี pivot/chart/image OCR, macro, encrypted workbook, old XLS/XLSB, formula cache faults, Shift-JIS, locale ทุกประเทศ หรือ schema ทุกชนิด ยังต้องเพิ่มไฟล์จริงที่ลบข้อมูลลับและ family ใหม่ที่เก็บไว้ไม่ให้ผู้พัฒนาเห็น

ไม่แก้ source ของ FORMA ไม่แก้เฉลยชุดเดิม และไม่ commit
